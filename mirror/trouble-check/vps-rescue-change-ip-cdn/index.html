2. 网站服务 (HTTP/HTTPS) 零成本复活：接入 Cloudflare CDN

如果你的 VPS 主要用于搭建个人博客、商业官网、API 接口服务或 Docker Web 容器，那么恭喜你：IP 被Q对你来说根本不是问题！

救砖秘籍

Cloudflare 橙色云朵（Proxy）代理中转原理

只要将域名的 DNS 解析托管在 Cloudflare，并在控制台将该域名的解析状态由灰色（DNS only）切换为橙色（Proxied 代理）：

  1. 中国大陆用户访问你的网站时，DNS 只会解析到 Cloudflare 在全球各地的 Anycast 边缘节点 IP。
  2. Cloudflare 边缘节点收到请求后，通过其高速跨国私有骨干网络，直接与你 VPS 的源站 IP 建立海外内部连接。
  3. 结果：你的真实 VPS IP 被完全隐藏在中转层之后，国内访客可以 100% 顺畅秒开网站！

3. 运维跳板自救：IPv6 直连与 SSH ProxyJump

如果你的 IPv4 已经彻底无法直连，但系统里面还有大量数据库和代码急需导出，可以用以下两种运维跳板通道救砖：

① 奇迹通道：使用原生 IPv6 连接 VPS

大部分阻断仅针对 IPv4 地址池。目前国内三大运营商的手机热点和家庭宽带普遍普及了 IPv6。如果你的 VPS 拥有 IPv6 地址：

通过 IPv6 地址直接绕过 IPv4 阻断登录 SSH
bash
#现代 OpenSSH 客户端原生支持 IPv6。只要加上 -6 参数，就能通过 IPv6 通道正常登录。
$ssh -6 root@2400:8902::f03c:91ff:fe24:xxxx

② 利用海外正常 VPS 作为 ProxyJump 代理跳板

如果你手头有另一台可以正常连接的海外 VPS（或公司跳板机），利用 OpenSSH 原生的 -J 管道转发参数，一键穿透连接被Q机器：

通过 ProxyJump 跳板机穿透登录被阻断的 VPS
bash
#数据在海外跳板机处完成转发，本地完全不需要直连被阻断的 IP 即可完成终端操作与数据导出。
$ssh -J root@海外正常跳板机IP:22 root@被阻断的VPS_IP -p 22

4. 紧急数据打包与备份命令 (VNC 应急)

在更换 IP 或重装系统之前，请先通过服务商后台的 Web VNC 登录控制台，快速将网站根目录与数据库打包：

一键打包网站数据与 MySQL 数据库
bash
#将数据库与 Web 目录整合打包为 full_backup.tar.gz，为迁移或重装做好准备。
$sudo mysqldump -u root -p --all-databases > /backup_db.sql && sudo tar -czvf /root/full_backup.tar.gz /var/www /etc/nginx /backup_db.sql
