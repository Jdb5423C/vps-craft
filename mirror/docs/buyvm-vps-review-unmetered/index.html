# 一、先分清两条产品线：KVM Slice 与 Block Storage Slab

BuyVM 的套餐库里同时存在两种完全不同的商品，而它们的名字长得很像，这是新手踩坑的第一现场。

# 1. KVM Slice：真正能开机的那一类

带 buyvm-lv-512、buyvm-ny-1g 这类 id 的，是 KVM 虚拟化的 VPS，配置形如 1C / 512MB / 10GB NVMe，端口 1Gbps。它可以装系统、跑 Docker、开网站，是一台完整的服务器。入门价 $3/月，往上依次是 $5/月 的 1GB 内存款与 $10/月 的 2GB 内存款。

需要提醒的是，512MB 内存只适合极轻量场景。Debian 12 裸系统大约吃掉一百多 MB，再装一个面板、一个数据库，余量就非常紧张。如果你的目标是「一台能长期稳定挂着服务的小机器」，1GB 起步会舒服得多，多出来的两美元买的是不用天天盯着 OOM 的安心。

# 2. Block Storage Slab：只能存数据，不能单独开机

带 buyvm-lv-slab-256、buyvm-ch-slab-1t 这类 id 的，是块存储。套餐表里写着 0C / 0MB / 256GB Block Storage，这个「0C / 0MB」经常被误认为数据缺失，其实它表达得非常准确：这块商品里没有 CPU、没有内存，只有容量。它必须挂载到同一机房的一台 KVM Slice 上，格式化后才能使用。

价格阶梯几乎是线性的：

容量月付价格折合每 GB
256GB$1.25约 $0.0049
512GB$2.5约 $0.0049

粗略算一下就知道它便宜到什么程度：一台 $3/月 的 512MB Slice，加一块 $1.25/月 的 256GB Slab，总价 $4.25/月，你就得到了一台带 256GB 存储的小服务器。同样的预算，在多数商家那里只能买到 20~40GB 的系统盘。

# 3. Slab 适合放什么，不适合放什么

适合的场景很明确：Nextcloud / Seafile 这类私有网盘的数据盘、Plex / Jellyfin 的媒体库、rclone 的落地目录、日志与监控数据的冷归档、CI 构建缓存、以及给容器挂一个独立的数据卷。

不适合的场景同样明确：高并发数据库、频繁小文件随机写的业务、需要低延迟 FSync 的交易型应用。块存储解决的是「容量贵」的问题，不是「IOPS 不够」的问题。把 MySQL 的 data 目录放到最便宜的 Slab 上，然后抱怨「怎么这么慢」，属于用错工具。

💡 一条容易被忽略的工程约束：Slab 只能挂到同一机房的 Slice 上，跨机房不能挂载。所以正确的顺序是「先定机房，再买 Slice，最后加 Slab」，而不是先抢一块便宜的存储再慢慢找机器。另外，删除实例前务必先确认数据已迁出——块存储是「一块盘」，不是「一份备份」。

# 4. 第三方块存储实测：一个 2020 年的样本

公开的 BuyVM 块存储跑分并不多，LowEndTalk 上有一份 2020 年底的 YABS 记录可以作为量级参考：机器为 1 核 Ryzen 9 3900X、约 981MiB 内存、270.6GiB 磁盘，帖内讨论确认这组 IO 是跑在 Slab 而非 NVMe 主盘上的。fio 混合读写 50/50 的结果是：4K 块读写各约 27.4 MB/s（约 6.8k IOPS），64K 约 83 MB/s，512K 约 266 / 280 MB/s，1M 约 273 / 291 MB/s；同一台的 iperf3 到伦敦方向发送约 1.12 Gbps。

这组数字说明两件事：顺序大文件吞吐能到两三百 MB/s，够媒体串流和备份用；4K 随机只有六千多 IOPS，和 NVMe 完全不在一个量级。这正是「容量换性能」的典型曲线，也解释了为什么它适合当仓库、不适合当数据库盘。

数据来源：LowEndTalk（https://lowendtalk.com/discussion/169062/buyvm-slabs-arrive-in-luxembourg-ryzen-free-snapshots-free-routed-48-ip-load-balancing-oh-my/p2），采集于 2026-11-07。

第三方实测受时间、机房、运营商与库存影响，本站未复现；套餐与网络条件以商家实际业务为准。该样本发布于 2020 年，硬件代次与当前在售机型未必一致，请只把它当作量级参考，不要当作性能承诺。

# 二、Unmetered 的真实边界：不限流量，但不等于不限资源

# 1. 数据库里的 1000TB 是什么意思

套餐表里，KVM 款的流量字段统一写着 1000.0TB @ 1 Gbps。这不是商家承诺「每月给你 1000TB」，而是本站归档时对「不限流量」做的一个量化占位。商家对外的正式表述是 Unmetered：不按 GB 计费、不因超额停机、不产生超额账单。

从物理上算一下更直观：1Gbps 端口 24 小时满载，一个月大约也就 300TB 量级。也就是说，1000TB 这个数字在 1Gbps 端口上根本跑不满，它更像是一个「形式上填个数」的字段，而不是可以消费的额度。真正决定你能怎么用的，不是这个数字，而是下面这份 AUP。

# 2. 官方 AUP 怎么界定「滥用」

BuyVM 的 Acceptable Use Policy 对资源滥用的定义只有一句话，但覆盖面很广：

1,1,1 - Resource Abuse consists of any activity, intentional or otherwise, that consumes sufficient system resources to negatively affect other clients or equipment.

数据来源：BuyVM 官方 AUP（https://buyvm.net/aup），采集于 2026-11-07。

翻成中文就是：任何（无论故意与否）消耗了足够多系统资源、从而对其他客户或设备造成负面影响的行为，都算资源滥用。注意两个关键词：一是「无论故意与否」，意味着「我不是故意的」不构成免责；二是「影响其他客户」，判断标准是结果，不是你的主观意图。

处理流程也写在 AUP 里：先把违规服务下线并保持 suspended，然后开工单说明问题与整改要求；用户回复确认后恢复服务，并给 24 小时整改窗口；拒不处理则继续 suspend，极端情况终止。也就是说，BuyVM 不是「一发现就删号」的风格，但对「已读不回」没有耐心。

# 3. 社区里流传的「公平使用」口径

官方从未公布过一份「每 GB 内存对应多少带宽」的表格，但 LowEnd 圈子里长期流传一个经验值：每 4GB 内存对应约 100Mbps 的持续占用。按这个口径推算，512MB 的入门款大约对应 12.5Mbps 的长期平均，折算下来每月双向各 4TB 左右；短时 burst 冲到几百 Mbps 则被认为是正常的。

这个说法在 HostBalls 论坛 2019 年的一条帖子里被拿到台面上讨论，BuyVM 的 Francisco 回复了「Yep, that all sounds fine」，并未否认；同帖还有「CPU 允许约 15% 持续占用」的说法。需要强调的是，这是论坛里的社区口径 + 官方人员的一句认可，不是写进 TOS 的 SLA。

数据来源：HostBalls 论坛（https://hostballs.com/t/buyvm-network-and-experiences/1745），采集于 2026-11-07。

💡 实操建议：把「不限流量」理解为「不用为流量做预算」，而不是「可以 24×7 跑满端口」。备份同步、媒体串流、镜像分发这类有明显波峰波谷的用法最安全；如果你打算长期占用半条端口跑 PCDN、做公共代理出口或大规模爬虫，那已经接近 AUP 的射程了。

# 4. 不该碰的红线

AUP 里另有两类「立即终止 + 永久拉黑」的行为：未经同意的批量邮件（1,2,2），以及明知故犯地托管恶意内容（1,3,3）。除此之外，扫描、爆破、DDoS、侵权内容同样属于高风险行为。

关于卢森堡机房，本站测速资料里有一句「抗版权投诉（DMCA Free）」的归档描述。这句话只能当作社区对该机房取向的概括，不是法律意见，更不意味着可以托管盗版资源——AUP 1,3,2 明确写了「违反所在国法律的内容」不被允许。把「DMCA Free」当成「想放什么放什么」，是最危险的误读。

# 四、四个机房怎么选：拉斯维加斯、纽约、迈阿密、卢森堡

BuyVM 的 92 条套餐记录里，美东占 46 条、美西 23 条、欧洲 23 条，基本是三分天下。四个机房各有明确的定位，选错了不是「慢一点」，而是「绕地球一圈」。

先澄清一个常见的名称混淆：部分中文资料把美西节点写作「洛杉矶」，但本站套餐库、测速 IP 与官方测速域名（lv）都指向拉斯维加斯。本文统一按拉斯维加斯表述，下单时也请以结算页显示的城市为准。

# 1. 拉斯维加斯（Las Vegas）：默认主力，美西首选

209.141.56.135 是拉斯维加斯的测速 IP，提供 100MB 与 1000MB 两个测速文件，标注来源为 community（社区整理，非官方页面直接公布）。从国内访问，美西是物理距离最近的一组，SSH 手感、面板操作、拉取 GitHub 与 Docker Hub 的体验通常最跟手。

它也是块存储铺货最积极的机房之一，buyvm-lv-slab-256 这类入门 Slab 长期是「补货即秒空」的状态。如果你的用户主要在亚太，或者你只是想要一台延迟别太离谱的练手机，默认从这里开始。

# 2. 纽约（New York）：面向美东与欧洲业务

198.98.53.31 是纽约的测速 IP，同样提供两个尺寸的测速文件，来源标注为 community。纽约的价值不在于「国内访问快」，而在于它离欧洲骨干与大西洋海缆更近：访问欧美 API、跑 CI 构建、同步 S3、对接支付网关，往往比美西更顺。

反过来说，如果你的主要访问者在中国大陆，纽约的物理延迟注定高于美西，晚高峰的抖动也更难预测。为国内用户选纽约，通常是用错了机房。

# 3. 迈阿密（Miami）：美东南枢纽与拉美门户

迈阿密是四个机房里测速资料最完整的一个：198.251.82.2 是测速 IP，Looking Glass 入口 https://speedtest.mia.buyvm.net/ 与 100MB / 1000MB 测速文件都标注为 official（官方公布）。

它的地理意义很明确：美东南枢纽，同时是通往南美与加勒比的跳板。如果你的业务涉及拉美用户、或需要覆盖美东偏南的区域，迈阿密比纽约更合适；对纯中国大陆用户来说，它没有特别的线路优势。

# 4. 卢森堡（Luxembourg）：欧洲节点，但名字有个坑

欧洲节点的测速入口是 198.251.86.22、https://speedtest.lu.buyvm.net/，100MB 与 1000MB 测速文件均为 official。这一组数据本身没有问题。

  • 商家违约的例外：若商家无理由单方终止服务，按剩余周期比例退款。
🛑 警告

三种「以为能退」的典型翻车场景：

1. 用支付宝下单，第二天觉得延迟高想退——不退，TOS 5,4,1 写得很清楚；

2. 用 PayPal 付款但账户未认证，或者拖到第四天才开工单——大概率不退；

3. 申请「立即取消」并以为系统会自动退款——只是终止服务，钱进 account credit。

# 优点（Pro）

  1. 流量模型简单：不按 GB 计费，不用每天算「这个月还剩多少」，对备份、串流、镜像分发这类用法极其友好；
  2. 块存储单价罕见：$1.25/256GB、$5/1TB 的线性定价，在整个低价 VPS 市场里都属于第一梯队；
  3. 产品组合灵活：小 Slice 负责计算、大 Slab 负责容量，按需拼装，不必为用不上的 CPU 买单；
  4. 机房覆盖合理：美西、美东、美东南、欧洲各有一个点，能覆盖大部分地理需求；
  5. 支付对国内友好：支付宝与 PayPal 都在官方清单里，没有外币卡也能下单；
  6. 官方测速透明：四个机房都有 IP 与下载文件，买之前可以自己验，而不是只看别人的截图。

# 缺点与避坑（Con）

  1. 缺货是常态：热门机房的 Slab 与入门 Slice 经常整月无货，且没有官方排队机制，能否买到取决于你多久看一次结算页；
  2. 退款窗口极窄：只有 PayPal（须认证）与卡的首单 3 天内可退，支付宝与加密货币直接出局，冲动的代价是全损；
  3. 线路不是优化线路：普通国际 BGP，晚高峰国内方向可能抖动，别拿它做国内直连的生产业务或游戏加速；
  4. Slab 的 IO 不适合数据库：便宜来自「容量换性能」的取舍，随机小 IO 是它的短板；
  5. 入门配置偏小：512MB / 10GB 只够跑极轻量服务，装个面板 + 数据库就见底；
  6. 命名与归档存在不一致：欧洲套餐标「瑞士」而测速走「卢森堡」，下单前必须在结算页确认机房；
  7. 风控严格：资料、IP、支付信息不一致可能被取消订单，且支付宝订单不退。

# 这些人群不适合 BuyVM

  • 需要 7×24 稳定国内直连的生产站：没有 CN2 GIA / 9929 / CMIN2，晚高峰不可控；
  • 需要跑数据库或高 IO 业务的人：Slab 的定位就不是这个，KVM 自带盘又太小；
  • 不能接受「先到先得」的人：缺货时你等一周也未必买得到，客服也不会给你预留；
  • 必须支持微信 / 银联的人：这两项均未核实，不能当作可用；
  • 想要「不满意就退」的人：3 天窗口 + 支付宝不退，几乎没有试错余地；
  • 完全不想碰命令行的新手：无管理服务，系统、挂载、迁移都要自己来。
