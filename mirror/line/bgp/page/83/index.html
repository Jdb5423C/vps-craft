「国际 BGP」是整个 VPS 行业里最被滥用的一个词。它既可以是「全球 20 个机房任选、带宽便宜到不限量」的性价比之选，也可以是「晚高峰延迟 300ms、丢包 10%」的灾难现场——因为 BGP 本身只是路由协议，它不承诺任何质量。这个页面讲清楚：BGP 线路什么时候够用，什么时候必须加钱换 CN2。

一、BGP 到底是什么，为什么它不保证速度

BGP（Border Gateway Protocol，边界网关协议）是互联网自治系统（AS）之间交换路由信息的协议。机房通过 BGP 把自己的 IP 段广播给上游运营商，运营商的流量再按路由表转发过来。

关键在于：BGP 只负责「能找到路」，不负责「这条路快不快」。同一个机房可以同时接电信、联通、移动、Cogent、NTT、Telia 等十几家上游，出口走哪家、走哪条国际光缆，取决于当时的 BGP 选路策略和拥塞情况。所以「BGP 机房」的真实含义是「多线接入、自动选路」，而不是「优化线路」。

二、普通国际 BGP 的真实表现

据华纳云 2026 年 10 月对香港普通 163 骨干线路的实测：白天非高峰延迟约 40–60ms，晚八点到十一点国际出口带宽被娱乐流量占满后，延迟飙升至 150ms 以上、丢包率 5%–10%，而同期 CN2 GIA 节点可以稳定在 0.5% 以下丢包、延迟波动 ±5ms。

美国方向更明显。萤光云 2026 年 5 月的线路说明指出，普通国际线路从海外机房回国大部分延迟在 200–300ms，且路由经常绕路（比如洛杉矶 → 西雅图 → 日本 → 上海，而不是直连）。这类线路应对国内访客的典型体感就是「图片一块一块刷出来」。

三、四种情况，BGP 完全够用

  • 用户全在海外。面向欧美、东南亚本地用户的站点，国内回程质量毫无意义，BGP 的多机房覆盖反而是优势。
  • 静态资源 + CDN 兜底。源站只返回 HTML，静态资源全部交给边缘节点，200ms 的源站延迟被 Cloudflare 吃掉大半。
  • 后台管理型业务。偶尔登录后台、跑批量任务，不需要低延迟，只要不断线。
  • 成本敏感的大流量场景。备份节点、下载站、离线数据处理，BGP 的带宽单价通常只有 CN2 GIA 的几分之一，且常标注不限流量。

四、五种情况必须加钱换优化线路

  • 面向国内用户的正式站点。晚高峰 5%–10% 丢包会直接体现在跳出率上；
  • API / 实时接口。抖动比延迟更致命，±50ms 的波动会让前端超时逻辑失效；
  • 远程桌面 / SSH 高频操作。200ms 以上的延迟打命令会明显「粘手」；
  • 游戏加速 / 联机。物理延迟是硬约束，优化不出来；
  • 跨境电商后台。部分平台对登录 IP 的 ASN 与延迟有风控判断。

五、怎么验证你买到的到底是什么线路

商家页面的「BGP」标签不能信，自己测三步：

  1. 看回程 AS 号：用 路由追踪 跑回国内的最后一跳，落在 59.43（CN2）、218.105 / 210.51（AS9929）、219.158（AS4837，联通 169）、202.97（电信 163）分别对应不同线路；
  2. 看跳数与绕路：美国西岸回上海正常 12–16 跳，如果出现日本、香港节点说明在绕路；
  3. 晚高峰复测：晚上 21:00–22:00 再跑一次 边缘 Ping 测试，对比白天的数据。差值超过 3 倍就说明这条 BGP 没有做优化。

六、BGP 之外的替代方案

  • CN2 GIA：电信最高等级，价格最贵，适合对延迟零容忍的业务，见 CN2 GIA 专题；
  • AS9929：联通高端 A 网，联通用户首选，见 AS9929 专题；
  • AS4837：联通 169 优化，性价比最高的一档，见 AS4837 专题；
  • CN2 GT：部分路径走 CN2，比普通 BGP 略好、比 GIA 便宜，适合折中预算。
