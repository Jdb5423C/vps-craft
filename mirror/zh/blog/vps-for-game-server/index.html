二、为什么「单核性能」比「核心数」重要

这是游戏服和网站服务器最大的区别。以 Minecraft 为例，它的主循环（tick）是单线程串行的：每秒跑 20 次，每次要把所有实体、方块更新、红石、AI 算一遍。不管你给多少核，主循环只用一个核。

所以：

  • 4 核 3.5GHz 比 8 核 2.4GHz 更适合 MC：主循环跑得快，TPS（每秒 tick 数）才稳；
  • 老 Xeon E5 系列（2.2–2.6GHz）是短板：便宜但单核弱，10 人以上就会掉 TPS；
  • 新平台（EPYC 7003/9004、Ryzen、i9）单核强：同样的钱，能多带 50%–100% 的玩家。

怎么判断一台机器的单核性能？看两个指标：

  1. CPU 型号的主频：3.5GHz 以上算好，2.5GHz 以下算弱；
  2. Geekbench 5/6 单核分数：MC 服务端建议 1200 分以上（Geekbench 5）。

多核也不是完全没用：区块生成、世界保存、插件异步任务会用到多核。所以「4 核高主频」比「2 核超高主频」更均衡。

三、内存怎么算：不是「越大越好」

1. Minecraft

MC 的内存占用分三块：堆内存（JVM Heap）、堆外内存（NIO、Netty）、系统缓存。你能控制的是堆内存，用 -Xms / -Xmx 设置。

玩家数原版 / Paper轻量插件（10 个以内）整合包（100+ 模组）
1–5 人1–2GB2GB4–6GB
5–15 人2–4GB4GB8–10GB
15–30 人4–6GB6–8GB12–16GB
30 人以上8GB+12GB+20GB+

关键原则：给 JVM 的内存不要超过物理内存的 70%。比如 4GB 的机器，-Xmx 最多设 2.8GB，剩下的留给堆外内存和系统。设满了会触发 swap，反而更卡。

另一个常见误区是「内存越大越不卡」。实际上堆内存过大，GC（垃圾回收）停顿时间会变长，表现为「每隔几十秒卡一下」。所以 4GB 的机器不要设 -Xmx4G，设 2.5–3GB 反而更稳。

2. 幻兽帕鲁

帕鲁是典型的「内存怪兽」。根据官方和社区实测：

  • 官方推荐：4 核 16GB 起步；
  • 2–4 人小队：4 核 8GB 可以跑，但据点建大后会吃紧；
  • 4–8 人：4 核 16GB（官方推荐配置）；
  • 8 人以上：8 核 32GB，且需要更好的单核性能；
  • 每增加一名在线玩家，大约多占 500MB–1GB 内存。

帕鲁还有一个特点：内存会随运行时间缓慢增长（内存泄漏或缓存累积）。长期开服建议配置定时重启（比如每天凌晨 4 点），并监控内存曲线。

磁盘方面：服务端程序 + 世界存档建议预留 40GB 以上，据点建得大的世界增长很快。

四、带宽怎么算：别让「上传」成为瓶颈

游戏服的带宽消耗是持续上行为主（服务器要把世界状态推给每个玩家）。粗算公式：

看起来需求不高？但有两个坑：

  1. 月流量会爆：10 人 MC 服，按 3Mbps 算，一天跑 8 小时，一个月约 1TB。很多便宜 VPS 只给 1TB/月，跑满就限速；
  2. 突发流量：玩家进入新区块、世界保存、插件同步时会瞬时打满端口。

所以选机器时，除了看端口带宽（1Gbps 基本都够），更要看月流量额度。MC 服建议 2TB 起，帕鲁建议 4TB 起。

# 测端口是否通（MC 默认 25565）
nc -zv 你的服务器IP 25565

六、防 DDoS：游戏服是头号靶子

游戏服是最容易被攻击的服务之一，原因很简单：攻击者能立刻看到效果（玩家掉线）。常见攻击类型：

  • UDP 反射放大：伪造源 IP 打你的游戏端口，流量能到几百 Gbps；
  • 协议层攻击：伪造 MC 握手包，占满连接数；
  • 假人攻击：用机器人占满服务器槽位，让真玩家进不来。

防护分三层：

层级方案成本效果
1. 隐藏源站只让玩家连中转 IP（如 Cloudflare Spectrum、TCPShield）免费–$10/月挡住 90% 的流量攻击
2. 协议层防护MC 用 TCPShield / Velocity 反代，开启握手验证$5–$20/月挡住假人与协议攻击
3. 高防 IP云厂商的高防包（100Gbps+）$30–$300/月硬抗大流量，但贵

对个人小服来说，第 1 层就够了：把源站 IP 藏起来，只暴露中转地址。如果真的被盯上，再考虑上高防。

另外几个基础防护：

  • 开白名单：white-list=true，只允许指定玩家进；
  • 限制连接频率：用 iptables / nftables 限制单 IP 并发；
  • 关掉查询：enable-query=false，减少信息泄露；
  • 定期更新服务端：很多攻击利用的是旧版本漏洞。

七、Minecraft 实战：Paper + Aikar 参数

1. 为什么用 Paper 而不是原版

Paper 是 Spigot 的分支，做了大量性能优化（实体合并、区块加载优化、异步寻路）。社区实测：同样的硬件，Paper 能带 3–5 倍的玩家。4 核 8GB 跑 Paper 1.21.x，稳定支持 40 人；原版 15 人就开始卡。

2. 安装步骤

BASH 
# 1. 装 Java 21（Paper 1.21 需要 Java 17+，推荐 21）
apt update && apt install -y openjdk-21-jre-headless
java -version

# 2. 建目录
mkdir -p /srv/mc && cd /srv/mc

# 3. 下载 Paper（版本号去官网查最新）
curl -o paper.jar https://api.papermc.io/v2/projects/paper/versions/1.21.4/builds/232/downloads/paper-1.21.4-232.jar

# 4. 首次启动（生成配置）
java -Xms1G -Xmx2G -jar paper.jar --nogui
# 同意 EULA 后重启

3. Aikar 启动参数（性能翻倍的关键）

Aikar 是 Paper 的核心开发者，他给出的 JVM 参数被社区公认为「MC 服务端最佳实践」：

SHELL / COMMAND 
java -Xms4G -Xmx4G \
  -XX:+UseG1GC \
  -XX:+ParallelRefProcEnabled \
  -XX:MaxGCPauseMillis=200 \
  -XX:+UnlockExperimentalVMOptions \
  -XX:+DisableExplicitGC \
  -XX:+AlwaysPreTouch \
  -XX:G1NewSizePercent=30 \
  -XX:G1MaxNewSizePercent=40 \
  -XX:G1HeapRegionSize=8M \
  -XX:G1ReservePercent=20 \
  -XX:G1HeapWastePercent=5 \
  -XX:G1MixedGCCountTarget=4 \
  -XX:InitiatingHeapOccupancyPercent=15 \
  -XX:G1MixedGCLiveThresholdPercent=90 \
  -XX:G1RSetUpdatingPauseTimePercent=5 \
  -XX:SurvivorRatio=32 \
  -XX:+PerfDisableSharedMem \
  -XX:MaxTenuringThreshold=1 \
  -Dusing.aikars.flags=https://mcflags.emc.gs \
  -Daikars.new.flags=true \
  -jar paper.jar --nogui

这几个参数的作用：

  • UseG1GC：用 G1 垃圾回收器，停顿更短；
  • MaxGCPauseMillis=200：目标停顿 200ms 以内；
  • AlwaysPreTouch：启动时预分配内存，避免运行中抖动；
  • DisableExplicitGC：禁止插件手动调用 GC（很多插件乱调，导致卡顿）。

4. 关键配置（server.properties）

SHELL / COMMAND 
view-distance=8          # 视距，8 是性能与体验的平衡点，不要设 16
simulation-distance=6    # 模拟距离，比视距更吃性能
max-players=20
online-mode=true         # 正版验证，盗版服改 false
white-list=true
enable-query=false
network-compression-threshold=256
entity-broadcast-range-percentage=75

视距是性能杀手：从 10 降到 8，CPU 占用能降 30%。玩家几乎感觉不到差别。

5. 用 systemd 托管

SYSTEMD 
[Unit]
Description=Minecraft Paper Server
After=network.target

[Service]
Type=simple
User=mc
WorkingDirectory=/srv/mc
ExecStart=/usr/bin/java -Xms4G -Xmx4G -jar paper.jar --nogui
Restart=on-failure
RestartSec=10
# 优雅关闭：先发 stop 给控制台
ExecStop=/bin/sh -c 'echo stop > /srv/mc/stdin'
StandardInput=pipe

[Install]
WantedBy=multi-user.target

注意 Restart=on-failure 而不是 always：MC 正常关服不算失败，用 always 会导致「关不掉」。

八、幻兽帕鲁实战：SteamCMD 部署

BASH 
# 1. 装依赖（Ubuntu 22.04/24.04）
apt update && apt install -y steamcmd

# 2. 建用户（不要用 root 跑）
useradd -m -s /bin/bash palworld
su - palworld

# 3. 下载服务端
steamcmd +force_install_dir ~/server +login anonymous +app_update 2394010 validate +quit

# 4. 启动
cd ~/server
./PalServer.sh -port=8211 -players=8 -publiclobby

关键点：

  • 端口是 UDP 8211，不是 TCP，防火墙规则别写错；
  • 必须用 SSD：机械盘会导致世界加载极慢；
  • 内存监控：帕鲁会缓慢吃内存，建议配 4GB swap 兜底；
  • 定时重启：每天凌晨重启一次，释放累积内存。

配置文件在 Pal/Saved/Config/LinuxServer/PalWorldSettings.ini，可以调经验倍率、捕获率、死亡惩罚等。

十、存档备份：丢了就真没了

游戏服最痛的场景不是「被攻击」，而是「玩了三个月的存档没了」。备份方案：

SHELL / COMMAND 
#!/bin/bash
# /srv/backup.sh
set -e
DATE=$(date +%Y%m%d-%H%M)

# 1. 通知玩家（RCON 或后台命令）
# echo "say 服务器将在 1 分钟后备份" | rcon-cli

# 2. 保存世界
# echo "save-all" | rcon-cli

# 3. 打包
tar -czf /srv/backup/world-$DATE.tar.gz -C /srv/mc world world_nether world_the_end plugins config

# 4. 保留最近 7 天
find /srv/backup -name "world-*.tar.gz" -mtime +7 -delete

# 5. 同步到对象存储
rclone copy /srv/backup remote:vps-backup/mc

十二、十个常见坑

  1. 用 HDD 开服：世界加载慢到怀疑人生，必须 SSD；
  2. 把 -Xmx 设成物理内存的 100%：触发 swap，反而更卡；
  3. 视距设 16：CPU 直接吃满，8 才是甜点；
  4. 忘了开 UDP 端口：帕鲁是 UDP 8211，只开 TCP 会连不上；
  5. 用 root 跑服务端：一旦有漏洞，整台机器沦陷；
  6. 不限制月流量：10 人 MC 服一个月能跑 1TB，超了限速；
  7. 没做备份：存档丢了找不回，三个月白玩；
  8. 被 DDoS 后直接换机器：源站 IP 已经暴露，换了还是被打；
  9. 装太多插件：每个插件都在主线程跑，10 个插件能吃掉 30% 性能；
  10. 忘了更新：旧版本有已知漏洞，容易被利用。

十四、开服后的日常运维

很多人以为「服务端跑起来就完事了」，实际上真正的活都在后面。一套能长期跑的服，需要四件事：

1. 看 TPS，而不是看 CPU

TPS（Ticks Per Second）是 Minecraft 的心跳，正常是 20。低于 18 就会开始感觉到卡，低于 15 基本没法玩。

SHELL / COMMAND 
# 游戏内命令
/tps

# Paper 自带
/paper tps

# spark 插件（推荐）
/spark tps
/spark profiler start
# 跑 30 秒后
/spark profiler stop

spark 的 profiler 能直接告诉你「哪个实体/插件/区块占了最多 tick」，是排障的终极武器。

2. 监控与告警

用 Uptime Kuma 监控 TCP 25565 端口，挂了推 Telegram。另外监控磁盘（世界存档会涨）和内存（帕鲁会泄漏）。

3. 定时重启

SYSTEMD 
# /etc/cron.d/mc-restart
0 4 * * * mc systemctl restart minecraft

# 重启前 5 分钟广播
55 3 * * * mc echo "say 服务器将在 5 分钟后重启" | rcon-cli

定时重启能解决 80% 的「越玩越卡」问题，尤其是帕鲁和大型模组服。

4. 日志与崩溃分析

SHELL / COMMAND 
journalctl -u minecraft -n 200 --no-pager | grep -i "error|exception"
ls -lt /srv/mc/crash-reports/ | head -5

MC 崩溃时会生成 crash-reports，里面直接写了「哪个模组/插件导致的」。看不懂就搜报错的第一行，通常能找到答案。

十五、插件与模组：少即是多

新手最容易犯的错是「一口气装 30 个插件」。每个插件都在主线程跑，装得越多 TPS 越低。下面是我认为「值得装」的清单，按优先级排序：

插件作用性能影响要不要装
LuckPerms权限管理极低必装
EssentialsX基础命令（家、传送、经济）低推荐
CoreProtect方块日志（防破坏）中（写数据库）推荐
WorldEdit / WorldGuard地形编辑与区域保护低（不用时）推荐
spark性能分析极低必装
ViaVersion跨版本兼容低看需求
Dynmap网页地图中高（渲染）看需求
CitizensNPC中看需求

几个原则：

  • 能不装就不装：原版 + Paper 优化已经能跑很好；
  • 不要装两个功能重叠的插件（比如两个经济插件）；
  • 装之前先看最近更新时间：两年没更新的插件可能有兼容问题；
  • 装完先测 TPS：如果从 20 掉到 15，果断删掉。

模组服（Forge / NeoForge / Fabric）另说：模组比插件吃资源得多，100 个模组的整合包至少 8GB 内存，且启动要 2–5 分钟。建议先用客户端跑一遍确认能玩，再上服务器。

十八、被 DDoS 后的应急响应

如果真的被打挂了，按下面顺序处理，不要慌：

  1. 先判断类型：ss -s 看连接数，iftop 看流量方向。流量打满 = 带宽攻击，连接数爆满 = 协议攻击；
  2. 立刻隐藏源站：把 DNS 改成 Cloudflare 代理（橙色云），或者上 TCPShield。这一步能挡掉 90% 的攻击；
  3. 换 IP：如果源站已经暴露且持续被打，只能换 IP。换完不要立刻在公开场合发新 IP；
  4. 开白名单：临时只允许已知玩家进，减少攻击面；
  5. 保留证据：tcpdump -w attack.pcap 抓包，必要时发给服务商；
  6. 评估是否值得继续：如果被持续针对性攻击，考虑换游戏类型或上商业高防，个人服很难长期硬抗。

不要做的事：不要在原来的 IP 上硬抗（流量会越打越大）、不要公开抱怨攻击者（会引来更多攻击）、不要相信「付费防 DDoS 插件」（拦不住流量层攻击）。

常见热点问题解答 (FAQ)

1 核 1GB 能开 MC 服吗？

能，但只能带 2–3 人，且视距要降到 6，插件不能装。建议 2 核 2GB 起。

盗版服怎么开？

online-mode=false。但要注意：盗版服容易被扫描、被攻击，建议配合白名单和 IP 限制。

需要独立 IP 吗？

需要。共享 IP 无法绑定端口，且容易被牵连。

和朋友分摊费用合法吗？

合法。自建服不涉及商业运营，几个人平摊服务器费用是常见做法。

能用家里的电脑开服吗？

能，但需要公网 IP 或内网穿透，且电脑不能关机。VPS 的优势是 7×24 在线。

延迟多少算正常？

MC 150ms 以内可玩，CS2 80ms 以内，帕鲁 150ms 以内。超过这个范围会明显影响体验。

被 DDoS 了怎么办？

先换 IP + 隐藏源站（用 TCPShield 等中转），再考虑高防。不要在原来的 IP 上硬抗。

能用 Docker 开服吗？

能。itzg/docker-minecraft-server 是最成熟的镜像，支持自动升级、模组加载、备份。代价是多一层网络开销（几乎可忽略）。

存档怎么从旧服迁移？

把旧服的 world、world_nether、world_the_end 三个目录打包，解压到新服同名目录即可。注意版本要一致，跨大版本需要用工具转换。

需要备案吗？

境外 VPS 不需要。但如果用国内云厂商开服且面向公众，需要备案（纯游戏端口通常不涉及）。
