一、先搞清体系：AWS Free Tier 的三大组成

许多人误以为“AWS 免费”就是把所有东西都免费用一年，这是产生误扣费的根本根源。AWS 官方将免费资源划分为截然不同的三类，控制台每一个服务的右上角都会有明确的标记：

  • 1. 12 个月免费（12-Month Free）：从账户注册首日起计算，持续整整 12 个日历月（365天）。主要包括特定机型的 EC2 云服务器、S3 对象存储（5GB）、EBS 云硬盘（30GB）、RDS 关系型数据库等。致命点在于：第 366 天没有任何停机确认弹窗，系统会自动无缝转为按需计费（On-Demand）从绑定的信用卡扣钱。
  • 2. 永久免费（Always Free）：面向所有新老客户，永久有效、永不过期。只要当月资源消耗不超过官方规定的阈值，就永远出账 $0。包括每月 100 万次调用的 AWS Lambda、25GB 存储的 Amazon DynamoDB、每月 1TB 出站流量的 CloudFront CDN 等。这是搭建 0 元无服务器架构（Serverless）的核心。
  • 3. 短期体验试用（Short-Term Trials）：从首次激活该服务之日起算，通常提供 30 天或 60 天的限时试用（如 Amazon Redshift、SageMaker、QuickSight 等大数据与 AI 容器服务）。试用期一过立即按小时扣费。

政策深度剖析：新账户吃亏了吗？
答案是：不吃亏，反而对新手更加友好和安全。
1. 任务赚取额外 $100 额度：新用户注册后进入控制台，AWS 设立了 5 个非常简单的新手引导任务（例如：创建一项 AWS Budgets 预算规则、在控制台启动一台 EC2 实例、体验调用一次 Amazon Bedrock 生成式大模型、部署一个基础 Lambda 函数等）。每完成一项即可获得 $20 抵扣金，5 项全部完成即可拿满额外的 $100 额度，总计 $200。
2. 机型性能飞跃：老账户被锁死在单核 1GB 内存的 t2.micro 上，连跑个 Docker 或编译个 Node.js 项目都会爆内存死机；新账户可以任选 2GB 内存的 t3.small 或者单核能效比极佳的 AWS 自研 Graviton2 ARM 处理器 t4g.micro / t4g.small。
3. 彻底告别信用卡半夜扣款恐慌：在注册时选择 Free Plan，一旦你的 $200 额度用光，或者 6 个月期限到达，AWS 会直接挂起你的虚拟机并发出邮件通知，绝不会私自从你的信用卡中划扣一分钱。只有你主动在控制台将其升级为 Paid Plan，才会进入按量付费模式。

三、2024 公共 IPv4 收费新政：免费层的隐藏暴雷点

在所有可能导致新手账单暴雷的原因中，公共 IPv4 地址（Public IPv4 Address）收费是 2024 年至今中招率最高的一项。

新政背景：由于全球可分配的 IPv4 地址彻底耗尽，AWS 官方宣布自 2024 年 2 月 1 日 起，对所有分配给 AWS 资源（无论是 EC2、NAT 网关、RDS 还是负载均衡器 ALB）的公共 IPv4 地址统一征收 $0.005 / IP / 小时 的费用。按一个月 730 小时计算，每个公网 IPv4 每个月将固定产生约 $3.65 美元（约合人民币 26 元）的基础费用。

Free Tier 对 IPv4 的豁免规则与三大致命雷区

为了兼顾学习与开发者的利益，AWS 在免费套餐中增加了一项专项补贴：为每个账户每月提供 750 小时的 EC2 专属公共 IPv4 地址免费时长。但这 750 小时背后隐藏着三个致命的连环雷区：

  • 雷区 1：750 小时刚好且仅够“单台机器 7×24 小时开机”。一个月 31 天总计 744 小时。这意味着，如果你在同一个账户下同时开通了 2 台带公网 IP 的 EC2，两台机器每小时总计消耗 2 个小时的额度，到了每个月的第 15 天左右，750 小时的配额就会被彻底耗尽！剩下的半个月内，你将立刻收到 IPv4 的按量扣费账单。
  • 雷区 2：闲置弹性 IP（Elastic IP / EIP）的惩罚性扣费。许多新手跟着教程申请了 Elastic IP（静态弹性 IP）。请牢记 AWS 的铁律：只有当 EIP 绑定在处于“运行中（Running）”的实例上时，它才不计闲置费。一旦你将实例关机（Stopped），或者该 EIP 处于未分配（Unattached）状态，AWS 会判定你在恶意囤积 IPv4 资源，按 $0.005/小时不间断征收惩罚性费用！一个月下来就是 $3.65 冤枉钱。
  • 雷区 3：非 EC2 服务的公共 IP 完全不享受免费豁免。这是最惨烈的踩坑点！750 小时的 IPv4 免费额度仅限 EC2 实例。如果你创建了 Amazon RDS 数据库并勾选了“Publicly Accessible（公开访问）”，或者在 VPC 中建立了 NAT Gateway，或者使用了面向公网的 ALB（应用负载均衡器），它们所分配的公网 IPv4 从创建的第 1 秒起便开始按 $0.005/小时计费，没有任何免费抵扣！

五、手把手实操：AWS 免费服务器 (EC2) 申请与零扣费开通保命指南

如果你需要申请并开通一台标准的 AWS 免费服务器（EC2 Linux 虚拟机）用于学习、建站或部署测试，请严格按照以下经过实测的避坑步骤操作：

第 1 步：账号注册与信用卡预授权

访问 AWS 官网注册账号，输入常用邮箱并设置强密码。在绑定信用卡环节，必须提供支持外币支付的双币/全币种信用卡（Visa / Mastercard / Amex）。系统会向银行发起一笔 $1.00 USD 的预授权扣费 用于验证卡片真实有效性，此交易通常会在数分钟至数天内自动解除返还，并非真实扣款。

第 2 步：账号安全基准——立即创建 IAM 普通用户（重要安全铁律）

绝对不要日常使用 Root 根账户进行开发与开机！
一旦 Root 账户的 Access Key 泄露到 GitHub，黑客会在 5 分钟内为你开满高配 GPU 挖矿机，造成数万美元天价损失。
正确操作：注册后立刻进入 IAM 控制台，创建一个具有 AdministratorAccess 权限的普通 IAM 用户，为其开启控制台访问权限并设置 MFA（谷歌验证器等二次认证）。退出登录，之后的所有日常操作均使用该 IAM 用户完成。

第 3 步：选择资源丰富的基准机房（Region）

在控制台右上角选择区域。建议首选 us-east-1（弗吉尼亚北部） 或 us-west-2（俄勒冈），因为美东美西机房的免费层库存最充足、各类新功能最全；如果注重国内访问延迟，可选择 ap-southeast-1（新加坡） 或 ap-northeast-1（东京），但创建实例时需仔细核验是否标有绿色“Free tier eligible”图标。

第 4 步：启动实例（Launch Instance）的精细配置

  1. Name and tags：自定义实例名称（如 my-free-ubuntu）。
  2. Application and OS Images (AMI)：推荐选择官方标有“Free tier eligible”的 Ubuntu 24.04 LTS 或 Amazon Linux 2023。切勿选择带有 Red Hat Enterprise Linux (RHEL)、SUSE 或商业版 Windows Server 的镜像，否则会产生每小时独立的操作系统授权费。
  3. Instance type（实例类型）：
    • 如果是 2025-07-15 前注册的老账户：勾选 t2.micro（1 vCPU / 1GB）；
    • 如果是 2025-07-15 后的新账户：优先选择 t4g.micro（ARM 架构）或 t3.micro（Intel 架构），有 $200 额度支撑。
  4. Key pair (login)：点击创建新的密钥对，类型选择 RSA，格式选 .pem，点击创建并下载保存到本地（如 ~/.ssh/aws-key.pem），并设置权限 chmod 400 ~/.ssh/aws-key.pem。严禁丢失，AWS 默认禁用密码登录。
  5. Network settings（网络安全组）：
    • 勾选“Allow SSH traffic from”：出于安全考虑，强烈建议将 Anywhere (0.0.0.0/0) 改为 My IP（仅限你的本地 IP），防止暴力破解；
    • 勾选“Allow HTTP traffic from the internet”与“Allow HTTPS traffic from the internet”以备建站。
  6. Configure storage（磁盘配置 - 最核心避坑点）：
    • 默认通常为 8GB。你可以将其提升至 20GB ~ 30GB（免费配额上限为 30GB）；
    • 卷类型保持为 通用型 SSD（gp3），IOPS 保持默认 3000、吞吐量保持 125 MB/s（这是 gp3 的免费基线，切勿手动调高数值）；
    • 点击高级展开项，务必确认“Delete on Termination”（实例销毁时删除）已勾选为 Yes！否则未来你删除该机器时，这块 30GB 的硬盘会残留为“孤儿卷”在后台持续扣费。

确认右侧 Summary 栏目中明确提示“Free tier eligible”，点击 Launch instance 启动虚拟机。至此，一台标准的 0 元 EC2 便部署成功。

六、8 大真实血泪扣费陷阱深度盘点（无数开发者血本无归的痛点）

根据 V2EX、知乎、Reddit 等开发者社区多年来的真实被扣费案例汇总，以下 8 大陷阱占到了 AWS 新手意外账单的 95% 以上：

陷阱 1：NAT Gateway 刺客（新手教程的最大祸害）

惨烈表现：很多新手跟着网上高深架构教程创建自定义 VPC 时，教程轻描淡写地写了一句“在公有子网创建一个 NAT Gateway 并配置路由表，使私有子网实例可以出网”。新手照做后，次月账单瞬间飙升 $32.40 刀以上。
真相揭秘：AWS 的 NAT 网关完全不包含在免费层中！其收费高达 $0.045 / 小时（折合单台每月固定扣 $32.40）+ $0.045 / GB 的数据处理费。个人测试或轻量应用根本不需要 NAT 网关，直接将机器放在 Public Subnet（公有子网）并分配公网 IP 即可。如果确实需要私网隔离出网，可以使用免费的 t4g.micro 实例自行配置 iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE 做免费的 NAT Instance。

陷阱 2：闲置弹性 IP（Elastic IP / EIP）偷跑账单

申请了静态 EIP，以为只要不发流量就免费。事实上，只要挂载的 EC2 实例被关机（Stop），或者解绑后没有立即在 EC2 菜单中点击 Actions -> Release Elastic IP addresses（释放弹性 IP），系统就会立刻按照 $0.005/小时计费，一个月白白损失 $3.65。

陷阱 3：EBS 存储卷超额与遗留快照（Snapshots）

12 个月免费的 EBS 存储上限是 30GB。这个 30GB 是你账号下所有可用区、所有硬盘容量的总和：
- 如果你开了一台机器分配 20GB，又开了第二台分配 20GB，总计 40GB，超出的 10GB 立即按月扣费；
- 终止（Terminate）实例时，如果系统未勾选销毁卷，卷会变成“Available”状态继续吃配额；
- 手动制作的 EBS 快照属于独立备份，并不属于普通 gp3 卷的 30GB 免费空间。快照超期或超出 1GB 后，按每 GB 每月 $0.05 持续扣费。

陷阱 4：RDS 关系型数据库勾选 Multi-AZ 与备份超标

AWS 免费提供 750 小时的 RDS（支持 MySQL / PostgreSQL / MariaDB）。但它有严苛的前提条件：必须是 Single-AZ（单可用区部署）。
许多新手在创建 RDS 时，出于“生产高可用”直觉勾选了 Multi-AZ deployment（多可用区），AWS 会在备用区域同步拉起一台副本，不仅导致 750 小时在半个月内被双倍耗尽，而且 Multi-AZ 本身具有额外溢价，当月直接产生数十美元账单。

陷阱 5：天价出站流量税（Data Transfer Out）

虽然 AWS 自 2021 年底起良心地将每月免费出站公网流量从 1GB 提升到了 100GB/月（对大部分个人博客完全够用），但一旦你将 EC2 当作代理、大文件下载服务器，或者网站遭受爬虫遍历与 CC 攻击，一旦超出 100GB，后续流量费用高达每 GB $0.09（亚太区甚至高达 $0.12/GB）！1TB 的意外流量足以让你支付近百美元。防范最佳实践是：网站前端务必接入 Cloudflare 或配置 CloudFront（自带 1TB 免费出站额度） 进行请求缓存，将回源流量压降至最低。

陷阱 6：CloudWatch 详细监控（Detailed Monitoring）误点

在启动 EC2 时，高级选项里有一项“Enable detailed monitoring”。默认的基础监控（Basic Monitoring）是 5 分钟采集一次数据，完全免费；一旦勾选详细监控（Detailed Monitoring），系统将以 1 分钟频率采集指标，这些指标会作为 Custom Metrics（自定义指标）独立按个收费，多开几台机器光监控费就能烧掉几美元。

陷阱 7：跨区域（Multi-Region）遗忘幽灵实例

AWS 控制台左上角是全球区域切换菜单。很多用户今天在“美东弗吉尼亚”开了一台测试机，过两天在网上看教程又切换到“日本东京”开了一台。由于控制台每次只能查看当前选定区域的资源列表，很多用户完全忘记了自己在其他区域还挂着未关机的实例，导致全月总运行时长远超 750 小时，产生巨额双倍账单。

陷阱 8：12 个月大限一到，静默按需扣费

针对 2025-07-15 之前注册的老账户，最常见的翻车是第 13 个月。AWS 在 12 个月免费期结束时，**绝不会主动帮你停掉服务器**，也不会短信告知“免费期结束，是否关机”。它只会发一封容易被垃圾邮件箱收纳的提醒邮件，随后无缝开始按天划扣你的信用卡。务必在日历中设置 330 天倒计时提醒！

七、保命级安全防御配置（不花冤枉钱的黄金三件套）

注册完 AWS 账号后，在启动任何服务前，必须花 5 分钟在后台完成以下三道防线的部署，这是老手不被账单反杀的底层机密：

第一道防线：开启免费套餐使用告警（Free Tier Usage Alerts）

  1. 在控制台搜索并进入 Billing and Cost Management（账单和成本管理）；
  2. 在左侧导航栏找到 Billing Preferences（账单偏好设置）；
  3. 勾选 Receive Free Tier Usage Alerts（接收免费套餐使用提醒）；
  4. 填入你的主力接收邮箱。当任一免费服务的用量达到 85% 阈值时，AWS 会自动提前发邮件警示。

第二道防线：配置 AWS Budgets 成本预算（最核心的止损底线）

这是整个 AWS 使用过程中最重要的一步：配置一个金额为 $1.00 的绝对成本预算，只要账户产生任何哪怕几美分的支出，立刻收到报警！

  1. 在控制台搜索进入 AWS Budgets -> 点击 Create budget（创建预算）；
  2. 选择 Cost budget（成本预算），模板选择“Monthly cost budget”；
  3. 在“Budgeted amount（预算金额）”一栏填入 1.00（即 $1 美元）；
  4. 配置告警阈值（Threshold）：
    • 第一条规则：当 Actual spend（实际支出） 达到预算的 50%（即 $0.50）时，触发告警；
    • 第二条规则：当 Forecasted spend（预测支出） 达到 100%（即预测本月可能超 $1.00）时，触发告警；
  5. 填入你的个人邮箱并保存。只要后续有任何未关闭的磁盘、IP 在悄悄计费，你会在几个小时内立刻收到警报邮件，避免滚成几十美元的大坑。

第三道防线：开启 AWS Cost Anomaly Detection（异常成本检测）

在账单管理控制台中进入 Cost Anomaly Detection，点击启用。这是 AWS 官方基于机器学习的免费告警工具，一旦监测到你账户下的某项服务支出发生非正常的突增（例如被恶意刷量或误开了超高配机器），系统会自动评估异常并向你的邮箱发送紧急研判通知。

八、如果不幸被扣费了？官方豁免退款全攻略（Goodwill Refund 申诉模板）

如果很不幸，你已经看到了信用卡的扣费扣款账单，千万不要直接在银行端发起争议拒付（Dispute/Chargeback）！
直接拒付会导致你的 AWS 账号和身份信息永久列入欺诈黑名单，无法再次注册。AWS 官方在业内以“对新手初犯误操作极其宽容”著称，拥有一套不成文的 One-time Goodwill Refund（一次性善意豁免政策）。只要你是首次踩坑、金额在合理范围内、且已经主动关闭了产生费用的资源，通过工单申诉几乎可以 100% 成功退回扣款！

紧急自救标准 3 步处理流

  1. 第一步：即刻止损（最关键）。立刻登录 AWS 控制台，找出所有产生费用的资源，将 EC2 实例 Terminate、删除 EBS 磁盘、释放弹性 IP、删除 RDS 等。AWS 客服处理退款的前提是：涉事资源已经处于彻底关闭状态，确认你并非恶意白嫖。
  2. 第二步：在 Cost Explorer 查清扣费服务明细。确认扣费来自哪个具体的服务项（例如 Amazon Elastic Compute Cloud - Compute、VPC Public IPv4 或 Amazon Relational Database Service）。
  3. 第三步：提交工单申诉。点击右上角的 Support -> Support Center -> Create case，选择 Account and billing support，类型选择 Billing，并在工单正文中使用诚恳专业的英文说明情况。

九、不用了怎么彻底注销？资源清理终极核对清单（Teardown Checklist）

如果你已经完成学习测试，或者打算换用其他服务器，绝对不能只在控制台点击“关机（Stop）”。请对照以下 8 步排查清单，确保账户内 0 隐藏收费源：

  1. Release Elastic IPs：进入 EC2 控制台 -> Elastic IPs -> 检查是否有未使用的 IP，勾选后点击 Actions -> Release Elastic IP addresses；
  2. Terminate EC2 Instances：进入 Instances -> 勾选所有实例 -> Instance state -> Terminate instance（彻底销毁，不可恢复）；
  3. Delete Detached Volumes：进入 Elastic Block Store -> Volumes -> 筛选状态为 Available（已与机器解绑但仍在扣费）的磁盘，全部删除；
  4. Delete Snapshots：进入 EBS -> Snapshots，删除所有手动生成或自动备份的快照；
  5. Delete RDS Databases：进入 RDS 控制台，删除所有数据库实例，勾选“不创建最终快照（Do not create final snapshot）”；
  6. Delete NAT Gateways & ALBs：进入 VPC 控制台删除所有 NAT Gateways；进入 EC2 控制台删除所有 Load Balancers；
  7. Clean CloudWatch Alarms & Logs：删除自己创建的高频自定义告警与超额日志组；
  8. Empty & Delete S3 Buckets：进入 S3 控制台，先清空存储桶对象，然后彻底删除存储桶。

如果你确认今后再也不使用该 AWS 账户，点击右上角账户名 -> Account -> 滑动到最底部，点击 Close Account（注销账户）。注销后账户将在 90 天后彻底物理销毁，期间不会再产生任何新费用。
