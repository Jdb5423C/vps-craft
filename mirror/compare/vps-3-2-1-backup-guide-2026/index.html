恢复演练：备份成功之后还要做什么

先写下恢复时间目标 RTO 和可丢失数据窗口 RPO，再选择备份频率。数据库使用自身支持的逻辑导出或一致性快照；直接复制正在写入的数据文件可能得到不可恢复的副本。备份主机凭据不要同时拥有生产环境删除权限，异地副本也不能与生产机器共用唯一的账户和付款方式。

SHELL / COMMAND 
mkdir -p /var/backups/app
# Example for a directory that has been quiesced or snapshotted:
rsync -a --numeric-ids /srv/app-data/ /var/backups/app/
tar -czf /var/backups/app-data.tar.gz -C /var/backups app
sha256sum /var/backups/app-data.tar.gz > /var/backups/app-data.sha256
sha256sum -c /var/backups/app-data.sha256
# Inspect before restoring; extract into a separate staging directory.
tar -tzf /var/backups/app-data.tar.gz | head

命令只示范归档完整性，不会自动验证数据库语义。将副本恢复到新的目录或临时 VPS，检查文件权限、应用密钥、数据库版本、账号登录和关键业务操作；记录实际耗时，最后清理测试凭据。不要在唯一的生产目录中直接试验覆盖恢复。

Linux 备份策略与工具：rsync、tar、borg 到底怎么选

在运维圈有句话：备份不做，事故必到。硬盘会坏、机房会淹、手会滑——唯一能让你睡安稳觉的，是一份可靠且验证过的备份。但"备份"两个字背后门道很多：全量还是增量？本地还是异地？直接拷文件还是逻辑导出？这篇文章先把 3-2-1 法则讲透，再带你用 rsync、tar、borg/restic 三种工具实际备一次，并强调一个被 90% 人忽略的真理：没演练过的恢复，等于没备份。

一、3-2-1 备份法则

这是业界金标准：3 份数据副本、2 种不同介质、1 份异地（离线或云端）。含义是：你手里至少要有原始数据 + 两份备份；备份不要都放同一块硬盘；其中一份要离你的机器远一点（比如对象存储、另一台远程服务器），这样本地火灾/勒索软件也带不走它。很多人只做"同机复制"，本质是零备份——硬盘一挂全没了。先有法则，再选工具，顺序不能反。

二、rsync：文件级同步与硬链接快照

rsync 是 Linux 备份的瑞士军刀，增量传输、只传变化的部分，极省带宽。最经典的玩法是用 --link-dest 做"硬链接快照"：每天一份新目录，没变的文件用硬链接指向昨天的文件，既保留多版本又几乎不占额外空间。排除缓存用 --exclude。推到远程走 SSH（ed25519 密钥优先）。危险操作 --delete 会删除目标端多余文件，务必先用 -n 演练再真正执行，否则可能清空目标目录。

SHELL / COMMAND 
rsync -a /data/ /backup/2026-08-06/
rsync -a --delete --link-dest=/backup/2026-08-05/ /data/ /backup/2026-08-06/
rsync -a -e "ssh -p 22" /data/ user@host:/backup/
rsync -avn --delete /data/ /mirror/

三、tar：最朴素的归档打包

tar 把一堆文件打成一个 .tar.gz，适合一次性全量归档或随人带走。zcvf 创建压缩包，xvf 解包，-C 指定解包位置，--exclude 排除目录。它简单可靠、几乎所有系统都自带，是"懒人备份"的首选。缺点是增量能力弱（要靠 -g 快照文件），大目录反复打包也费 CPU。小网站、配置文件、一次性迁移，用 tar 最顺手。

SHELL / COMMAND 
tar zcvf backup_$(date +%F).tar.gz /etc /home
tar xvf backup_2026-08-06.tar.gz -C /tmp/restore
tar zcvf backup.tar.gz --exclude='*.cache' /home

四、borg / restic：去重 + 加密

当你备份量变大、又想异地存到不可全信的云盘，borg 和 restic 是当代答案。它们分块去重——相同内容只存一份，备份越多次反而越省空间；并且客户端加密，哪怕仓库在别人服务器上，别人也看不到你的数据。borg 用 repokey 模式，restic 支持 SFTP/对象存储等多种后端。备份完记得 prune 清理旧快照、check 校验完整性，防止静默损坏。

SHELL / COMMAND 
borg init --encryption=repokey /mnt/backup/borg-repo
borg create --stats /mnt/backup/borg-repo::$(hostname)-$(date +%F) /etc /home
borg prune --keep-daily=7 --keep-weekly=4 --keep-monthly=6 /mnt/backup/borg-repo
restic init --repo /mnt/backup/restic-repo
restic backup /etc /home

【备份系列 01】VPS 数据别裸奔：3-2-1 备份实战（快照+restic+rclone）2026

三层落地框架：快照 + restic + rclone

把 3-2-1 拆成三层，每一层干不同的活：

  • Layer 1 厂商快照：秒级回滚，适合"刚改坏配置想退回五分钟前"。快恢复，但非异地、非 immutable；
  • Layer 2 restic 版本化加密备份：把数据做块级去重、AES‑256 加密、保留多个历史版本，存到本地第二块存储或第二台机；
  • Layer 3 rclone 推异地对象存储：把 restic 仓库同步到 B2/Wasabi/R2 等对象存储，这才是真异地；
  • Layer 4 immutable（可选抗勒索）：对象存储开对象锁（Object Lock）/版本控制，让备份不可被篡改或删除。

这四层是互补关系，不是谁替代谁。快照管速度，备份管生存。

厂商快照与自动备份政策（详见系列第 3 篇）

各家厂商的快照计费、自动备份策略与保留天数差异很大而且经常变动——DigitalOcean 按 Droplet 月费的 20% 收自动备份、Vultr 按容量计费、CloudCone 按服务器月费 30% 收每日自动备份、RackNerd 大多无原生快照、Contabo 给 1 个免费快照。限于篇幅这里不逐项展开，完整对比表见本系列第 3 篇《VPS 备份策略：厂商快照政策对比与自建异地容灾》。但有一条对任何厂商都成立：快照与实例同存储、同账号、同 region，删实例常连带删快照，绝不能替代异地备份。

restic：加密去重版本化，VPS 异地备份的主角

为什么是 restic 而不是老牌 rsync？对比一下就清楚：

  • rsync：只同步文件、不去重、不内置加密（要加密得配 rclone crypt），好处是简单；
  • restic：客户端 AES‑256 加密、块级去重（相同文件几乎零增量）、原生直连 B2/S3 等对象存储、单一二进制跨平台、支持 forget/prune 保留策略；
  • borg：压缩更强，但得经 SSH 到另一台 Linux，不能直接写云存储（需配 rclone）；
  • duplicati：历史上有损坏 bug，口碑一般，不推荐。

结论：restic + rclone 是 VPS 异地备份最主流组合。restic 负责做加密去重仓库，rclone 负责把仓库推到异地。

一套可复刻的实战脚本：

  • 初始化仓库：restic -r b2:my-bucket:repo init；
  • 备份目录：restic backup /data；
  • 保留策略并清理：restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune（保留 7 天每日、4 周每周、6 月每月，旧版本自动剪掉）；
  • 推异地：rclone sync -P /backup/repo remote:backups/，担心影响业务可加 rclone --bwlimit 1M 限速。

数据库必须 dump 再备，别直接拷运行文件

这是新手最容易翻车的点：直接复制运行中的 MySQL/PostgreSQL 目录，恢复出来是崩溃不一致的。正确姿势是先导出：

  • MySQL/MariaDB（仅 InnoDB）：mysqldump --single-transaction > dump.sql；
  • PostgreSQL：pg_dumpall 或 pg_dump -Fc 导出；
  • Docker 状态在 named volume：要么先 dump，要么短暂 docker compose down 再备，否则卷里可能是半截状态。

然后让 restic 去备这个 dump 文件，而不是裸卷。一句口诀：数据库先 dump，再进备份流程。

异地对象存储怎么选：2026 价格落地

第三层要落到具体对象存储，2026 年实测价格如下（以各官网为准）：

  • Backblaze B2：约 $0.00695/GB·月（约 $6.95/TB·月），前 10GB 免费，上传免费，下载 $0.01/GB 但每月免费出口额度 = 前月平均存储量的 3 倍，通常恢复不花钱。restic 原生后端首选；
  • Wasabi：$6.99/TB·月（预留 1 年约 $5.99），无出口费，但有 90 天最短存储期（删早了也按 90 天计费），且 1TB 起；
  • Cloudflare R2：$0.015/GB·月（Standard，$15/TB·月），出口永远免费，前 10GB 存储 + 请求免费，适合恢复频繁/下载不可预测的场景；
  • Storj：约 $4/TB·月，去中心化、S3 兼容，三者中最便宜；
  • Hetzner Storage Box：约 €3.80/TB·月，出口免费，SFTP/REST 友好，适合 Hetzner VPS 用户；
  • AWS S3 Glacier：约 $0.004–0.036/GB·月（Deep Archive 最便宜），存储极廉但取回慢且按 GB 收费，适合冷归档。

一个 85GB 的备份池，年存储成本大约 US$4–24，几乎不是财务决策点。真正拦住大家不备份的，是"多开账号 + 生成密钥 + 配脚本"那半小时。所以别纠结价格，先动起来。

免费层数据备份最佳实践：被回收也不慌（2026）

核心法则：3-2-1（免费版）

经典 3-2-1：3 份数据、2 种介质、1 份异地。搬到免费层就是：① 源机一份（正在跑的）；② 同云快照 / 块存储一份（快速回滚）；③ 跨云对象存储一份（防单点）；④ 本地一份（最终兜底）。免费额度下，重点是用多家免费额度互相备份，而不是把钱花在单一厂商的付费备份上。

Oracle：快照 + 对象存储免费额度

Oracle 免费账户有块存储快照额度（与 200GB 块存储共享上限），定期给数据盘做快照即可快速回滚。对象存储（Object Storage）也有免费额度（标准桶一定容量内免费），可把关键文件 rclone 同步过去。注意：快照和源盘在同一个账号，若账号被封会一起没，所以跨云副本不能省。详细保活与回收逻辑见 Oracle 自救指南。

AWS / GCP：把免费层当"临时"，备份外溢

这两家的免费是限时的，12 个月后资源可能转付费或被清。正确姿势：把 AWS / GCP 免费层当作"试用 + 生成备份"的跳板——在上面跑的任务，其产出（数据库 dump、静态产物）定时同步到 Oracle 对象存储或本地。不要把自己唯一的数据副本留在 12 个月就到期的云上。对比见 四大免费云对比。

Cloudflare：无服务器也要备份

Cloudflare 免费栈（Pages / Workers / D1 / R2 / KV）虽然没"实例被回收"的问题，但配置和代码仍在。建议：① 源码永远在 Git 仓库（GitHub 是最终兜底）；② D1 / KV 的数据定期导出；③ R2 的桶可做版本控制。因为 Cloudflare 不给你"一台机器"，备份对象变成了"代码 + 数据 + 配置"三类。

一套可复用的脚本思路

不论哪家，备份的骨架都类似：① 定时（cron）在业务低峰做数据库 dump；② 用 rclone / aws cli / oci cli 把 dump 和关键目录同步到异地存储；③ 保留滚动版本（如最近 7 天 + 每月 1 份）；④ 偶尔做一次恢复演练，确认备份真的能还原。脚本本身也要进 Git，避免"备份脚本丢了导致没法备份"的套娃。

二手VPS买卖防坑指南2026：原油/改邮/PUSH过户怎么选，搬瓦工为何最易"被找回"

一、为啥绝版/传家宝 VPS 能溢价几百块卖

你可能在 Hostloc、闲鱼或者各种 TG 群里见过这种现象：一台年付才十几二十美元的 RackNerd 小机、或者搬瓦工（BandwagonHost）早年几十刀的 CN2 套餐，挂出来能卖到比原价贵几百块人民币。新手第一反应是"这人傻钱多？"其实不是，这背后是稀缺性 + 续费同价的逻辑。

绝版套餐的稀缺逻辑

  • 不补货：像搬瓦工的 CN2 GIA 28 美元套餐（原价 29.99）、双十一特价机，官方早就下架不再上货，市面上只会越来越少。
  • 续费同价：这是关键。很多绝版套餐是"首年特价、续费也还是这个价"，而官方现在在售的同配置可能已经涨到几倍，甚至根本不卖了。所以持有老套餐 = 长期锁定低价。
  • RackNerd 早期闪购：黑五、双十一那种年付 $10 左右的"传家宝"小机，因为续费不涨价、还能稳定用，被囤货党当硬通货炒。

供需关系很简单：卖家手里有"买不到的新价"，买家又想要低价且不想等补货，溢价就出来了。但溢价越高，坑也越多——下面慢慢拆。

二、二手 VPS 三种交易方式

圈子里二手 VPS 交接主要就三种姿势，安全和价格天差地别。

1. 原邮 / 原油（带原始注册邮箱，最安全最贵）

"原邮"指的是商家注册时第一次用的那个邮箱，里面通常还留着官方的 Welcome 邮件。交易时把整个邮箱账号连同 VPS 一起交给买家，买家拿到的是完整找回能力。这种最安全，所以价格也最高。常见邮箱是 Outlook、Gmail 或自建邮局。

注意：即便买了原邮，收过来也要做"邮箱防找回清洗"（见第四节），否则卖家用绑定的手机号/恢复码还能把邮箱夺回去。

2. 改邮（后台改绑定邮箱）

"改邮"是把商家后台账户绑定的邮箱改成买家的新邮箱，相当于变更账户归属。不同商家政策完全不同：

  • DMIT：后台可以直接改邮箱，相对规范。但要注意新账户/新购机器有 10 天冷却期，期间不能改邮也不能转移（这是个真实踩坑点）。改邮后基本无找回风险。
  • RackNerd：大多数套餐可以发工单申请改绑定邮箱，但一般只能改一次；改太多次官方会要求走付费 PUSH。部分特定闪购（Flash Sale）套餐限制改邮。
  • 搬瓦工：改邮风险极高（详见第三节），不推荐。

3. 官方 PUSH（最稳妥，付费但干净）

PUSH 是商家提供的官方过户功能：只把某一台机器从卖家账号转移到买家账号下，不涉及邮箱、密码、原始注册信息的交接。这是三种方式里最干净、最安全的。

  • netcup：免费 PUSH，卖家后台生成转移码，买家输入即可接收，条件是付清当前季度账单。
  • CloudCone：支持官方 PUSH 过户。
  • RackNerd：通过工单申请 PUSH，费用按"次"收不是按"台"收（一次 Push 多台到同一账号只付一次钱），金额早年 2 美元、后来涨到 8 美元，也有资料显示涨到 15 美元——以你交易时官方报价为准。流程：开 ticket 说明要 Push 哪几台到哪个账号 → 客服让确认 → 生成账单 → 付款 → 几小时内转移完成。
SHELL / COMMAND 
# RackNerd PUSH 大致流程（走工单，不是命令）
# 1) 登录卖家账号开 Support Ticket，写清：
#    - 要转移的 VPS 服务 ID 列表
#    - 目标买家账号的注册邮箱
# 2) 客服回复让你二次确认转移明细
# 3) 后台支付 Push 手续费账单（PayPal/信用卡）
# 4) 通常数小时内 VPS 出现在买家账号下
# 提示：转移中机器会短暂重启，提前备份数据

三、搬瓦工的特殊坑：API 找回 + TOS 严禁

搬瓦工是二手市场里坑最多的一家，老哥必须单独拎出来说。

TOS 明令禁止账户买卖

搬瓦工服务条款（ToS）写得很死：We do not allow assignment, sale, or transfer of customer accounts... Accounts involved in such activities will be terminated without refund. 翻译过来：不允许账户的出售/转让，参与此类活动的账户将被终止且不退款。官方客服也在 LOC 明确回过帖：账户会被"退回给原始所有者"。所以买搬瓦工账号本质是游走在封号红线上的钢丝。

原号主随时能"找回"

搬瓦工账户是以邮箱登录的，而最初注册那个邮箱 + 当时的支付凭证才是账户归属的铁证。即使中间被倒了十几手、改了无数次邮箱，原始号主只要拿最初邮箱去申诉，官方大概率把账户"还"给他——你付的钱和机器一起打水漂。这就是"原油最贵但最安全"的原因。

API 后门：不 reset 等于把钥匙留给了卖家

搬瓦工 KiwiVM 面板里有个 API 功能，能看到机房、IP、SSH 端口、内存、流量、CPU 占用、系统版本、MAC 地址，甚至当前账号主人的邮箱；还能换机房、改密码。如果卖家记录下了 API 信息，哪怕不知道你后来改的账户密码，也能直接操控这台机器。

所以接手搬瓦工机器的第一件事：进 KiwiVM 面板 → API 栏目 → 点 Reset 重置 API 密钥。这操作就 5 秒钟，能省掉无数后续麻烦。收机器后还要顺手做：改邮箱、改密码、重置 KiwiVM 面板独立密码、最后重装一次系统。

四、防骗指南（保住钱和机器）

  • 先查商家 TOS 是否允许转让：搬瓦工明令禁止，被发现连机器带余额一起没；DMIT、RackNerd 相对宽松但也要看具体套餐。交易前先 Google 一遍 "商家名 + account transfer TOS"。
  • 走担保/中介：除非和对方很熟，否则一律走第三方担保或托管平台。私下先付款再交接，没任何保障，圈子里为了 10 块钱骗人的都有。
  • 先验机再付款：让卖家提供 IP，自己先 ping / SSH 测一下、看面板能不能登录、IP 有没有被封锁或被标记（之前发过垃圾邮件的 IP 接手就废）。确认机器真实存在且状态正常，再付尾款。
  • 保留聊天记录：所有约定（套餐、到期时间、续费价、是否带原邮）截图留证，纠纷时起码有个凭据。
  • 分步付款：先付一部分定金，确认能登录、能改密、能 reset API，再付尾款。

买了"原邮"也要做邮箱防找回清洗

如果接手的是 Outlook/Hotmail 原邮，到手后必须：

  • 把安全邮箱替换成你自己的，并开启二次验证（或换成你的手机号）；
  • 在"从所有位置注销"里踢掉卖家所有设备的登录状态；
  • 重置并保存"恢复代码"，旧代码作废。

这三步少一步，卖家都有可能把邮箱再夺回去。

五、识别"假传家宝"：别被溢价冲昏头

  • 算清楚剩余价值：机器还剩多久到期？比如年付 $15 的机器只剩 2 个月，那实际剩余价值就两三刀，溢价 300 块买纯属冤大头。让卖家截图后台的 Renew Date 和续费价格。
  • 看续费原价还划不划算：有些"绝版"只是首年便宜，续费价已经涨到和官方在售同款一样，那稀缺性就是个伪命题。
  • 警惕"永久/绝版"话术：真高性价比的套餐根本没人低价甩，价格远低于行情的大概率是骗局；溢价动辄 300~500 元，这笔钱够买大半年的官方正价套餐了，性比价未必高。
  • 找回风险永远存在：只要不是官方 PUSH、不是带完整原邮，就有被原号主找回的可能。优先选支持官方过户的套餐（DMIT 改邮、netcup/CloudCone 免费 PUSH、RackNerd 付费 PUSH），安全性比私下改邮高一个量级。

一句话：二手 VPS 交易，核心永远是"安全"而不是"低价"。不确定的机器能凑活用就先凑活，真要新增不如挑近期高性价比的正价套餐，省心又安全。

【备份系列 02】VPS 数据备份 3-2-1：快照、rsync 与异地容灾实操

二、厂商快照省心，但别全指望它

像 CloudCone、RackNerd、Vultr 这类商家面板里大多带一键快照，点一下就能把整块系统盘冻结成镜像，恢复时几分钟内还原整个系统，连操作系统、装好的环境、配置文件一起回来。它最大的优点是快和简单：Kernel 升级翻车、装包把依赖搞崩，回滚快照比重装省事太多。但它有几个绕不开的坑。

第一，快照和你的实例在同一个底层存储集群，本质是"同城副本"，扛不住机房级灾难。第二，快照通常按容量计费，长期堆着不删很烧钱，Vultr 这类按小时计费的快照攒久了账单会让你肉疼。第三，快照是整盘镜像，想单独捞回一个被改错的配置文件得先挂盘，不够灵活。所以正确姿势是：快照当"近快速 rollback 用"，不是唯一的备份。重大操作（换内核、大版本升级、迁移）前手动打一个快照，平时别让它无限增长，配合下面两套真正异地、可筛选的备份才算完整。各家厂商快照具体怎么计费、自动备份保留几天，差异很大（CloudCone 按服务器月费 30%、RackNerd 多无原生快照、Contabo 给 1 个免费快照……），逐项对比见本系列第 3 篇。

三、rsync 异地同步：把文件甩到另一台机器

rsync 是 Linux 自带的老牌同步工具，强项是只传变化的那部分，第一次全量跑完，之后每次增量，带宽和时间都省。最典型用法是把网站目录同步到一台独立的备份机：

SHELL / COMMAND 
rsync -avz --delete -e "ssh -p 22" /var/www/ user@backup-vps:/backups/www/
rsync -avz -e "ssh -p 22" /etc/ user@backup-vps:/backups/etc/

参数里 -a 保留权限和时间戳，-v 看过程，-z 传输压缩；--delete 会让目标端和源端完全一致（删掉源端已删的文件），用之前想清楚，别把目标当存档。建议用 SSH 密钥登录，这样脚本能无人值守跑。数据库别直接 rsync 文件，要先落库：

SHELL / COMMAND 
mysqldump -u root -p --single-transaction --routines --triggers mydb > /backup/mydb-$(date +%F).sql
gzip /backup/mydb-$(date +%F).sql

--single-transaction 对 InnoDB 能做一致性导出而不锁表，生产库一定要加。PostgreSQL 用 pg_dump 同理。把数据库 dump 和网站文件一起 rsync 过去，这台备份机就是你的第二份副本。

四、rclone 上云：真正的异地副本

rsync 解决的是"第二台机器"，但两台机器可能在同一个机房甚至同一家厂商。要满足 3-2-1 里那"1 份异地"，最省心的办法是用 rclone 把备份推到对象存储——Backblaze B2、Wasabi、Cloudflare R2、AWS S3 都行，支持 40 多种后端。参考价：B2 和 Wasabi 这类冷存大约 0.006 美元/GB/月，50GB 异地备份一个月才几毛钱，比一杯咖啡便宜。

安装和配置一次即可：

BASH 
curl https://rclone.org/install.sh | sudo bash
rclone config
rclone sync /backup remote:bucket/vps-backup/ --bwlimit 10M --progress

sync 会保证远端和本地一致；--bwlimit 10M 限速避免把上行带宽打满影响业务。想保留历史版本就用 copy 而不是 sync，或配合存储桶的版本控制。注意 rclone 默认明文上传，敏感数据务必加 crypt 远程加密（见下一节）。这样你手里就有：本地快照 + 备份机 rsync + 对象存储 rclone，三份、两种介质、一份真异地，3-2-1 闭环。

五、加密与完整性校验：备份不能被看穿也不能坏掉

备份里往往有数据库、密钥、用户隐私，裸奔扔到云上等于把家底送给别人。rclone 自带 crypt 远程，配置时设一个强密码，之后同步到云端的全是密文，存储账号被盗也读不出内容。另一思路是用 restic 或 BorgBackup 这类支持端到端加密和去重的工具，restic 还能自动 prune 旧快照。

比加密更常被忽略的是完整性校验。一个悄悄损坏的备份，出事时才发现恢复不了，比没备份还坑。两个习惯要养成：一是用 --checksum 或 rclone 的校验和比对，确保传过去的和源文件一致；二是定期抽查恢复。简单校验示例：

SHELL / COMMAND 
rclone check /backup remote:bucket/vps-backup/
sha256sum /backup/mydb-*.sql.gz

rclone check 会逐文件比对哈希，告诉你两边是否对得上。把这份校验输出也存一份到异地，出问题时有据可查。

六、cron 自动化：别靠记忆力备份

手动备份的宿命是"周一一顿操作，然后忘了三个月"。所有备份必须交给 cron 定时跑。先把上面的逻辑写成一个脚本 /usr/local/bin/backup.sh，末尾清理过期文件：

SHELL / COMMAND 
#!/bin/bash
DATE=$(date +%F)
mysqldump -u root -pPASS --single-transaction mydb | gzip > /backup/mydb-$DATE.sql.gz
rsync -az -e "ssh -p 22" /var/www/ user@backup-vps:/backups/www/
rclone sync /backup remote:bucket/vps-backup/ --bwlimit 10M
find /backup -name "*.sql.gz" -mtime +7 -delete

注意密码写脚本里有泄露风险，生产环境建议用配置文件或密钥管理，这里只为演示。然后写进 crontab：

CRON 
crontab -e
0 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1

意思是每天凌晨 2 点跑一次，日志落盘。find ... -mtime +7 -delete 自动删 7 天前的库备，防止磁盘被备份撑爆。数据库业务频繁的话，可以把 binlog / WAL 归档也加进去，把恢复点压到分钟级。

【备份系列 03】VPS 数据备份实战：快照、rsync、Restic 与异地容灾怎么搭 2026

一、为什么 VPS 用户必须自己管备份

在共享主机上，服务商通常会帮你做备份甚至代你恢复；但一旦你上了 VPS，拿到 root 权限，备份的责任就完全落在自己肩上。VPS 给你足够的控制权，也给了你足够快把一切搞砸的能力。数据丢失几乎不是"会不会发生"的问题，而是"什么时候发生"的问题：误删目录、改错配置、磁盘故障、一次失败的升级、被入侵、甚至商家跑路，任何一条都可能让你几个月的工作归零。

我们见过太多真实案例：有人用 rm -rf 删错了路径，有人在一次升级后 Nginx 起不来，也有人在 ColoCrossing 或 RackNerd 上跑了一年业务却从没做过任何备份。等到真正需要恢复时，才发现什么都没有。这篇指南不灌鸡汤，只讲可落地的方案：自动快照、rsync 异地同步、Restic 加密增量备份到对象存储，以及最容易被忽略的恢复演练。

三、备份的三种形态，别混为一谈

很多人把"快照"和"备份"当成同义词，这是灾难的开始。它们解决的是不同问题。

形态代表工具优点缺点
整机快照商家控制台恢复快、一键回滚、适合新手通常同机房同账户，不等于异地
文件级备份rsync / restic可恢复单文件、长期保留更省空间整机恢复慢、需要自动化
异地备份对象存储 / 另一台 VPS真正能扛住商家跑路和机房火灾配置稍复杂、有少量成本

一个诚实的结论：快照不等于异地备份。快照和你的 VPS 躺在同一个商家的同一个账户里，如果商家账户被盗、被勒索，或者干脆跑路，快照也会一起没。快照的价值在于"刚才手滑删错，三分钟滚回来"，而不是"商家没了我的数据还在"。

四、第一层：商家快照与自动备份政策对比

针对本文面向的四家商家，我们整理了一份真实政策对比（具体以商家当下页面为准）：

从这张表能看出一个现实：便宜商家在快照上各有取舍。RackNerd 连原生快照都没有，意味着你从第一天起就该把 rsync/Restic 异地备份安排上；CloudCone 的自动备份按服务器月费 30% 收费，对低价套餐很划算；Contabo 给 1 个免费快照但仅此一个；ColoCrossing 的备份附加虽然便宜，但本质还是同商家的副本。再次强调：这些都不算异地。

五、第二层：rsync 异地同步

rsync 是 Linux 下最经典的文件同步工具，只传变化的块，适合把网站目录、配置文件增量搬到另一台 VPS。先在两台机器之间配好 SSH 密钥，让 cron 能无人值守运行：

SHELL / COMMAND 
ssh-keygen -t ed25519 -f /root/.ssh/backup_key -N ""
ssh-copy-id -i /root/.ssh/backup_key.pub backup@backup-host.example.com

最简单的同步命令：

SHELL / COMMAND 
rsync -avz --delete /var/www/html/ backup@backup-host.example.com:/backups/www/ \
  --exclude cache/ --exclude tmp/

这里 --delete 会让目标端镜像源端的删除。这既是 rsync 的方便之处，也是它最大的坑：源端一旦误删或文件损坏，破坏会忠实地同步过去。所以它更适合"服务器复制、迁移、暂存同步"，而不是需要时间点恢复的严格备份。

如果你想要带历史版本的 rsync 备份，可以用 --link-dest 做硬链接快照，每天一份、共用未变化的文件块，既省空间又能回滚到具体某天：

SHELL / COMMAND 
rsync -aAXH --delete \
  --link-dest="$DEST_ROOT/latest" \
  -e "ssh -i /root/.ssh/backup_key" \
  /var/www /etc /home \
  backup@backup-host.example.com:$DEST_ROOT/$DATE

再用 cron 每天凌晨 3:15 跑：

SHELL / COMMAND 
15 3 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1

诚实提醒：rsync 本身不加密、不版本化、不做去重。敏感数据建议在管道里套一层 gpg，或者干脆用下面要讲的 Restic。

六、第三层：Restic 加密增量备份（详见系列第 1 篇）

Restic 是这一层最值得学的工具：默认就做对三件事——AES-256 客户端加密、内容去重、块级增量，原生支持 S3、Backblaze B2、Cloudflare R2。它和 rsync 定位不同：rsync 是"镜像"，Restic 是"带版本、能加密去重的历史仓库"。完整的安装、初始化、备份/恢复命令与自动化脚本，我在本系列第 1 篇《restic + rclone 加密去重备份实战》里逐行写过了，这里不重复贴命令，只给结论：第一次备份 50GB 约几十分钟，之后每天增量 2–5 分钟；50GB 仓库放 B2 约 $0.30/月；口令丢了仓库永远打不开，务必离线保存。

对象存储本身不贵，2026 年参考价（以官方页面为准）：Backblaze B2 约 $0.006/GB·月（出流量 $0.01/GB，恢复常不花钱）；Cloudflare R2 $0.015/GB·月（出口永远免费）；Contabo 对象存储约 €0.010/GB·月（欧洲节点、S3 兼容）；AWS S3 $0.023/GB·月（出流量 $0.09/GB，适合 AWS 生态）。预算紧张的用户，R2 的零出口费与 Contabo 对象存储的欧洲节点最值得优先考虑。

【备份系列 04】VPS 快照备份哪家强 2026：免费快照额度、成本与恢复速度操作与验证：对比

一、快照和自动备份根本不是一回事

先把这个最基础的概念掰扯清楚。快照是某个时间点整台机器磁盘的一份"时点镜像"，手动触发、几乎即时生成，恢复也快，它的定位是"变更前的安全网"——比如升级内核、改防火墙之前打一个，出问题一键回滚。但它最大的失效场景就是：你忘了创建。

自动备份则是定时自动跑的完整拷贝，创建耗时从几分钟到几小时，恢复也慢一些，适合灾难恢复。它最大的失效场景正好反过来：你 10 分钟前刚改坏配置，而最近一次备份是 24 小时前。所以两者不是二选一，而是互补关系。一句话记忆：快照防手贱，备份防天灾，异地备份防跑路。

还有一个很多人不知道的关键局限：快照通常和源数据存在同一个存储系统上，如果原数据盘本身坏了，快照很可能跟着一起遭殃。所以严格说，快照不等于备份。

二、2026 年主流商家快照政策一览

直接上干货，这是 2026 年各家的政策对比（数据来自公开资料与实测）：

  • 搬瓦工 BandwagonHost：全部套餐免费快照，还免费自动备份，每隔几天自动做一次全量备份，走 KiwiVM 面板一键回滚。
  • Vultr：按压缩后大小收 0.05 美元每 GB 每月，快照可从面板直接跨区域部署新实例；自动备份是 VPS 月费的 20%。
  • DMIT：送 1 个免费快照，在线备份按 0.45 美元每 GB 每月收费。
  • ColoCrossing：无免费快照，手动快照 2 美元每月含 3 次全量，每月最多恢复 5 次；每日备份 10 美元每月，每周备份 5 美元每月。
  • Hetzner：无限免费快照，恢复约 2 分钟，是行业标杆（不过不在本站推荐列表里）。
  • DigitalOcean 与 Linode：无免费额度，0.05 到 0.06 美元每 GB 每月，恢复约 3 分钟。
  • Google Cloud：无免费额度，0.026 美元每 GB 每月，恢复约 3 分钟。
  • Contabo：快照额度与计费按所选产品的当前条款核对；恢复时间需要用自己的数据规模演练。
  • RackNerd：重点提示，当前没有任何快照功能，也没有自动备份，面板不支持；官方已确认在测试新面板、未来会加，但现阶段只能自己想办法。

三、快照成本的真实账：有的比 VPS 还贵

快照按存储量收费，存多了真能吃掉你一整个预算。以一块 20GB 的磁盘为例，如果长期保留 10 个快照，2026 年的年成本大约是：Hetzner 0 美元，Vultr 108 美元，DigitalOcean 120 美元，Linode 144 美元。对比一下，很多 VPS 一年也就十几二十美元——快照费比机器本身贵好几倍，就是这么来的。

算账时还有两点要注意：第一，商家按压缩后的大小计费，20GB 的盘实际用了 12GB，快照大概就是 12GB 上下，不会按总容量算；第二，快照大小约等于已用磁盘空间，所以打快照之前把盘清理一下，能实打实省下钱。

四、恢复耗时：建立可复算的演练记录

恢复时间受到数据量、镜像、地区、资源配额和应用启动过程影响。本文没有保留原始恢复日志，因此不发布商家之间的分钟数排名。记录发起恢复、资源就绪、数据库恢复完成与关键业务通过验证四个时间点；完整 RTO 还包含 DNS、证书与人工处置，不能只用控制台显示“运行中”的时间计算。

恢复速度是很多人忽略的硬指标。真到出事故的时候，每多等一分钟都是煎熬，能选快的就别选慢的。多说一句，恢复速度不是唯一指标，但它是用户的第一道体验门槛——2 分钟和 10 分钟的差距，有时候就是"救得回来"和"眼睁睁看着业务断"的差距。如果你把快照当成主要防线，这一项请务必看进眼里。

五、组合拳：快照加自动备份加异地备份

光靠商家自带的快照，永远躲不过"商家跑路""整盘损坏"这类最坏情况。2026 年更稳妥的做法是三层防护：第一层，商家快照，变更前手动打一个，成本 0 到 5 美元每月；第二层，商家自动备份，防意外删除和损坏，成本约等于 VPS 月费的 20%；第三层，异地备份到另一家商家或对象存储，防商家跑路和勒索软件，成本 1 到 5 美元每月。三层加起来每月 5 到 10 美元，数据安全基本就到位了。

异地备份的常用工具链不复杂：restic 支持加密、去重和快照，推荐保留策略是保留最近 7 天每天一份、最近 4 周每周一份、最近 6 个月每月一份；rclone 可以把数据同步到 S3、Backblaze B2、Google Drive 等地方。对象存储的参考价是 Backblaze B2 每 GB 每月 0.005 美元，20GB 的异地副本一个月只要 0.1 美元，几乎可以忽略。

数据库备份还有一个容易踩的坑：一致性。MySQL 打快照前先执行 FLUSH TABLES WITH READ LOCK，PostgreSQL 用 pg_start_backup，否则恢复出来的可能是损坏数据。喜欢自动化的朋友，Vultr 提供了完整的 API 脚本，可以定时自动创建并轮转快照，保留最近 4 个，用 cron 每周日凌晨 3 点跑一次。

常见热点问题解答 (FAQ)

校验和一致是否代表应用已经可以恢复？

校验和只能证明所比较字节一致，还要验证数据库一致性、权限、密钥、版本与关键业务操作。恢复到新的隔离目录或实例，避免用唯一生产副本做覆盖实验，并记录实际 RTO 与可恢复时间点。

同一账户下的快照算独立异地备份吗？

先看故障域、地域、权限和保留机制。账户删除、凭据泄露或付款中断可能同时影响所有快照；至少保留一个不依赖同一控制面的副本，并演练源账户不可用时的恢复。
