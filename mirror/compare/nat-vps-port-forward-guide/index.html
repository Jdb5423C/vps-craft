二、什么是 NAT VPS？一栋大楼里的一间房

普通 VPS 你花钱买的是「一个独立公网 IPv4 + 本机可用的全部端口」。NAT VPS 则相反：一台物理母机通常只有一个公网 IPv4，商家通过 NAT（网络地址转换）和端口映射，把这个 IP 下的不同端口分给不同的小鸡。

给你一个好懂的比喻：把那台母机想象成一栋大楼，整栋楼只有一个门牌号（公网 IP），楼里住着许多户人家（不同的 VPS 用户）。每户人家有自己独立的房间号（端口范围）。外面的人想找你，必须同时知道「门牌号 + 房间号」，快递才能准确送上门，不会送错到邻居家。

实际分配大致是这样（以下端口仅为示意，不代表任何商家的真实分配）：

  • 用户 A 分到端口范围 20000–20019
  • 用户 B 分到端口范围 20020–20039
  • 用户 C 分到端口范围 20040–20059

因为大家的端口互不重叠，虽然共用一个 IP，但通信各走各的、互不干扰。你在这台小鸡上跑的任何服务，外面都要通过 共享IP:你的端口 来访问。商家通常会在控制面板里提供端口映射表，或者在开通邮件、产品详情页里写明分配规则。

常见的 NAT VPS 会基于不同虚拟化技术实现：

  • KVM：完全虚拟化，每台小鸡是独立虚拟机，隔离性较强、功能较完整，但资源开销大；
  • LXC / LXD：操作系统层轻量虚拟化，共用宿主机内核，性能高、资源省，是很多低价 NAT 小鸡的首选；
  • OpenVZ 等容器方案：部署快、开销低，但隔离性弱，内核参数通常不可改，Docker 等嵌套能力取决于商家配置。

另外要注意：2022 年以后，很多 NAT VPS 实际上是「IPv6 小鸡 + 若干 NAT 进来的 IPv4 端口」。也就是说你通常还会拿到一个独立 IPv6 段（常见为 /64 或 /80，具体看套餐），IPv6 部分往往是完整可路由的——这一点在第五节会展开。

三、为什么能便宜？钱主要省在 IPv4 上

核心原因只有一个字：IP。

IPv4 地址早已分配殆尽，独立公网 IPv4 对商家来说是一项持续成本。你买一台普通独立 IP 的 VPS，套餐价格里有一部分其实是在替这个 IP 付租金；机房、上游运营商和地区差异还会让这项成本继续变化。

NAT VPS 的聪明之处在于：多个用户平摊同一个 IP 的成本。再叠加商家对内存、硬盘和带宽的适度复用（毕竟不是所有人同时跑满），硬件成本也被摊薄，于是低价年付套餐就成立了。至于具体能低到什么程度，取决于商家的促销、机房和超售策略，不能用一个固定数字概括。

还有一个隐性差异：NAT 小鸡通常没有可自助管理的 rDNS，也无法完全掌控 IP 信誉。这两样东西对建站、发邮件、做电商登录都是刚需，所以便宜不是没有理由的。

四、端口怎么用？先在面板做端口映射

买完 NAT 小鸡，第一步不是直接 SSH，而是先去商家控制面板确认端口映射（Port Forwarding）。商家一般会提供映射管理页面，让你把小鸡内部的端口，映射到共享 IP 上的某个外部端口；也有些商家采用「预分配端口段 + 固定规则」，不需要你逐条添加。

常见做法是：

  • 小鸡内部 SSH 是 22，商家把它映射到共享 IP 的某个高位端口，于是连接时要 ssh -p 外部端口 用户@共享IP；
  • 你想跑一个网页服务，内部 80 端口可以映射到外部的一个高位端口；
  • 想跑一个 Node 应用，内部 3000 映射到另一个外部端口。

有些商家会预分配一段连续端口，你自己在面板里把「内部端口 → 外部端口」配对好即可。小鸡启动通常比普通 VPS 慢一点，开通后等一段时间再测。下面是一张常用的端口规划表，端口号全部是示例，实际请替换成商家分配给你的值：

HTTP 源站8020080TCP供 CDN 或反代回源

验证端口有没有真正打开，可以用 tcping 工具（Windows 上常用），或者从外面 telnet 共享IP 外部端口 测连通性。如果连不上，先确认四件事：端口映射有没有保存、小鸡里服务有没有起来、本机防火墙有没有放行、以及这个外部端口有没有被商家或机房阻断。

更专业的测法是在小鸡上用 ss -tlnp 看监听状态，再从外部用 nc -vz 共享IP 端口 测；两边都正常说明链路通，只有一边正常说明是映射或防火墙问题。部分商家还会限制 UDP、限制可映射端口数量，或者要求工单开通额外端口，这些都要以产品页和工单回复为准。

五、IPv6：NAT 用户的隐藏福利

很多人不知道：NAT VPS 最大的隐藏价值是 IPv6。因为 IPv6 地址空间充足，商家通常会给每台小鸡分一个 /64 或 /80 段，而且是可路由的——不需要 NAT，支持 IPv6 的访客可以直接访问。

这意味着：

  • 你可以给网站配 AAAA 记录，让支持 IPv6 的访客直接连你的小鸡，绕过 IPv4 的端口限制；
  • 可以跑 IPv6 优先的服务（如某些邮件、FTP、游戏服），不受 IPv4 端口映射数量限制；
  • 可以用 IPv6 做内网穿透的备用链路。

代价是：IPv6 覆盖率仍不完整。部分企业网络、老旧路由器、公共 Wi-Fi 以及一些移动网络仍只有 IPv4。Google 的 IPv6 统计页面会实时展示全球采用率，具体数字每天都在变化，本文不写死一个百分比。所以生产环境仍然需要 IPv4 端口或 CDN 作为回退。

配置示例（以 Debian/Ubuntu 的 netplan 为例，地址与网关必须换成商家实际下发的值）：

SHELL / COMMAND 
network:
  version: 2
  ethernets:
    eth0:
      addresses:
        - 2001:db8:1234:5678::2/64
      routes:
        - to: default
          via: 2001:db8:1234:5678::1
      nameservers:
        addresses: [2606:4700:4700::1111, 2001:4860:4860::8888]

配完用 ping6 2606:4700:4700::1111 验证出网，再用外部 IPv6 测站工具确认入站可达。注意：能 ping 通不等于服务可达，还要检查本机防火墙是否放行了对应端口。

六、没有 80/443 端口怎么办？四套方案解决建站难题

NAT VPS 最大的痛点在于：你分到的通常是 10000 以上的高位端口，一般拿不到 80 和 443。而浏览器默认访问网站就是走 80/443。难道 NAT VPS 就不能建站了吗？当然不是。

方案 A：直接访问「域名:端口」或「IP:端口」

最简单粗暴——你的网站监听内部的 80，映射到外部的高位端口，那别人访问 http://你的域名:端口 就能看到。缺点是要带端口号，不够优雅，而且纯 HTTP 没有加密。适合自己和小圈子用的内部工具，不太适合正经对外网站。

方案 B：用 Cloudflare 等 CDN 前置（最推荐）

这是 LowEndBox 等社区最推崇的便宜建站法。思路是：把你的域名 DNS 解析托管到 Cloudflare，让 Cloudflare 的 IPv4 对外，再由 Cloudflare 回源到你的 NAT VPS。

由于 Cloudflare 的 Origin Rules 支持改写回源端口，你可以在规则里把目标端口改成 NAT 映射端口。访客走 Cloudflare 的 443，完全无感，还能使用 Cloudflare 的 SSL 证书和缓存加速。根据 Cloudflare 文档，目标端口可以是 1–65535 之间的值；真正需要落在「Cloudflare 代理支持端口列表」里的是访客访问 Cloudflare 边缘的端口，不是回源端口，这一点容易被旧教程混淆。

关键配置步骤（Cloudflare 后台）：

  1. DNS 里把 blog.example.com 的 A 记录指向 NAT 共享 IP，开启橙色云朵（代理）；
  2. Rules → Origin Rules → Create Rule：匹配 Hostname equals blog.example.com，把 Destination Port 改写为你的 NAT 映射端口（示例 20080）；
  3. SSL/TLS 模式选 Full 或 Full (Strict)；如果是 Full (Strict)，源站必须配一张 Cloudflare Origin Certificate 或受信任证书；
  4. 建议同时开启 Always Use HTTPS 与 Automatic HTTPS Rewrites。

Cloudflare 代理默认支持的访客端口是有限的：HTTP 为 80、8080、8880、2052、2082、2086、2095，HTTPS 为 443、2053、2083、2087、2096、8443。正常建站让访客走 80/443 即可，不需要让他们记住你的高位端口。另需注意，Cloudflare 免费套餐、代理规则和证书功能会调整，具体以控制台当前可选项和官方文档为准。

方案 C：借一台有独立 IP 的 VPS 做反向代理

如果你手头还有一台带独立 IPv4、能正常用 80/443 的 VPS（哪怕是另一台便宜货），可以让它当「门面」，用 Nginx 或 Caddy 把请求反代到 NAT VPS 的高位端口。

Nginx 反代配置示例（192.0.2.10 为文档示例地址，请替换为你的 NAT 共享 IP）：

NGINX 
server {
    listen 80;
    listen [::]:80;
    server_name blog.example.com;

    location / {
        proxy_pass http://192.0.2.10:20080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

改完记得检查并重载：

SYSTEMD 
sudo nginx -t
sudo systemctl reload nginx

嫌 Nginx 配置麻烦的话，Caddy 更省事，几行就能反代，还能自动申请 Let's Encrypt 证书：

SHELL / COMMAND 
blog.example.com {
    reverse_proxy 192.0.2.10:20080
}

这样访客访问 blog.example.com 的 80/443，实际内容来自你那台几美元的 NAT 小鸡。对访客来说，体验和独立 IP 建站基本一致。

方案 D：SNI 分流——一台 443 服务多个 NAT 小鸡

如果你有多台 NAT 小鸡，又只有一个独立 IP，可以用 SNI 分流把不同域名的 TLS 握手分到不同后端。Nginx 的 stream 模块配合 ssl_preread 就能做到：

NGINX 
stream {
    map $ssl_preread_server_name $backend {
        blog.example.com    10.0.0.11:20080;
        api.example.com     10.0.0.12:20081;
        default             10.0.0.10:443;
    }

    server {
        listen 443;
        proxy_pass $backend;
        ssl_preread on;
    }
}

注意：SNI 分流不终结 TLS，证书必须由后端自己提供（每台小鸡各自申请证书，或用 DNS-01 泛域名证书）。好处是一台入口机可以挂多台 NAT 小鸡，坏处是配置比 HTTP 反代复杂，而且排错时要同时看入口机和后端。使用前确认入口机的 Nginx 编译了 stream 与 ssl_preread 模块。

七、动态 IP 与 DDNS：IP 变了也不怕

部分 NAT VPS 的共享公网 IP 会变动（尤其是一些使用家宽或动态线路的商家）。一旦 IP 变了，你之前写死的域名解析就失效，连不上了。这时候就要上 DDNS（动态域名解析）：写个小脚本定期获取当前共享 IP，发现变了就自动更新 DNS 解析记录。

常见做法：

  • 用 Cloudflare、DNSPod 等服务的 API，写个短脚本，每隔几分钟获取出口 IP，再调用 API 更新 A 记录；
  • 把脚本丢进 crontab 定时跑，例如每 5 分钟一次；
  • 也有现成的开源 DDNS 客户端，配置好 token 就能自动维护。

一个最小可用的 Cloudflare DDNS 脚本（使用 jq 解析 JSON，变量要换成你自己的值）：

BASH 
#!/usr/bin/env bash
set -euo pipefail

ZONE_ID="你的_zone_id"
RECORD_ID="你的_record_id"
TOKEN="你的_api_token"
NAME="blog.example.com"

IP=$(curl -fsS -4 https://api.ipify.org)
CUR=$(curl -fsS -H "Authorization: Bearer $TOKEN" "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/dns_records/$RECORD_ID" | jq -r '.result.content')

if [ "$IP" != "$CUR" ]; then
  curl -fsS -X PUT -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" --data '{"type":"A","name":"'"$NAME"'","content":"'"$IP"'","ttl":120}' "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/dns_records/$RECORD_ID" >/dev/null
  echo "updated to $IP"
fi

注意：获取出口 IP 要用 NAT 共享 IP，不要用小鸡的内网 IP。部分商家会在面板里直接显示当前共享 IP，优先用面板值；如果出口 IP 与入站共享 IP 不一致，说明商家做了额外的源地址转换，此时 DDNS 应更新入站地址，必要时向商家确认。

八、NAT VPS 的极客妙用清单

说到底，NAT VPS 真正的价值在「便宜 + 能出网」，下面这些场景它比独立 IP 小鸡划算太多：

  • 探针 / 监控节点：买一堆分布在各地的 NAT 小鸡，24 小时 ping 你的主站、测家宽延迟、监控服务存活。阵列式监控如果用独立 IP 成本很高，用 NAT 几乎可以忽略。推荐 Uptime Kuma 自建，一台入口机加多台探针即可。
  • 轻量代理 / 中转落地：当「落地节点」或流量中转，把数据从 A 地经 NAT 小鸡转到 B 地。只要能出网、能连端口，完全不影响。
  • 小型数据库或反代节点：跑个轻量 Redis，或者像上面那样专职做 Nginx/Caddy 反代入口，把多个内部服务用域名区分转发。
  • DDNS 内网穿透入口：家里宽带没有公网 IP 时，用 NAT 小鸡加 frp/ZeroTier 做中转，把家里 NAS、摄像头、智能家居暴露出去。
  • 流媒体解锁落地：部分商家提供特定地区原生 IP 的 NAT 小鸡，用来做流媒体落地节点很合适；但 IP 段和流媒体政策会变，购买前应自行核实，本文不保证任何解锁效果。
  • Bot / 爬虫 / CI 跑腿：Telegram、Discord 机器人多数是「主动外连」，根本不需要别人连进来，NAT 完美适配且成本低。若使用 webhook 模式，则需要一个可达的入站端口。
  • 定时任务 / 数据采集：跑 crontab 拉 RSS、同步备份、采集公开数据，对端口零要求。

九、frp 内网穿透：把家里 NAS 接出来

NAT 小鸡最实用的玩法之一，是当 frp 服务端，把家里的 NAS、树莓派、监控摄像头接出来。frp 官方仓库将其定义为「把位于 NAT 或防火墙后的本地服务器暴露到互联网」的反向代理工具。

新版 frp 使用 TOML 配置，旧版 INI 已不再推荐。服务端示例：

SHELL / COMMAND 
bindPort = 7000
vhostHTTPPort = 20080
vhostHTTPSPort = 20443

auth.method = "token"
auth.token = "换成你的强密码"

客户端示例：

SHELL / COMMAND 
serverAddr = "共享IP"
serverPort = 27000

auth.method = "token"
auth.token = "换成你的强密码"

[[proxies]]
name = "nas"
type = "http"
localIP = "127.0.0.1"
localPort = 5000
customDomains = ["nas.example.com"]

启动顺序：先启 frps，再启 frpc。token 必须改，默认或弱 token 会被扫描器盯上。端口要落在商家分配给你的范围内，不能随意写。frp 版本迭代较快，配置字段以官方仓库当前文档为准。

十、安全：共享 IP 更要小心

NAT 小鸡因为共享 IP，被扫描的频率往往高于独立 IP——邻居被扫，整段 IP 都会被尝试。四件事必须做：

  1. 禁密码登录，只用密钥：设置 PasswordAuthentication no，并禁用 root 密码直登；
  2. 对外使用商家分配的高位端口：这能挡掉大量无差别暴力扫描。注意容器内 sshd 可以继续监听 22，由商家映射到高位端口；如果你同时改了 sshd 端口，记得同步修改映射；
  3. 装 fail2ban：默认配置就能拦掉大部分暴力破解；
  4. 开防火墙：只放行必要端口，默认拒绝入站。
SYSTEMD 
sed -E -i 's/^#?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -E -i 's/^#?PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart ssh
apt install -y fail2ban ufw
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw --force enable

另外：不要在 NAT 小鸡上登录重要账号。共享 IP 可能已被标记，触发风控时你很难申诉。数据库、面板、Docker API 等敏感服务不要直接暴露在公网端口上，至少加一层认证或只允许指定来源 IP。

十二、总结

NAT VPS 不是「阉割版 VPS」，而是一种把稀缺 IPv4 资源摊薄的聪明产物。它用「共享 IP + 端口映射」换来了极低的价格，代价是丢了 80/443 和独立可达性。只要你搞懂端口映射、用 Cloudflare 或反代解决建站、用 DDNS 兜住动态 IP，它就能胜任探针、反代、中转、Bot 跑腿等一大票轻量任务。

新手想低成本入门海外服务器，NAT VPS 是很实在的练手选择——先花十几块玩一年，把 Linux、Nginx、Docker 和防火墙都跑一遍，比只看教程强得多。但请记住：便宜来自共享，共享意味着你无法控制邻居和 IP 信誉。把重要业务放在独立 IP 上，把 NAT 小鸡当成工具箱里的一把轻便小刀，才是正确的用法。

常见热点问题解答 (FAQ)

NAT VPS 能建站吗？

能，但通常要配合 Cloudflare、域名转发或独立 IP 反代。直接用「域名:高位端口」也能访问，只是没有标准 443 的体验，SEO 和分享链接都不友好。

为什么映射了端口还是连不上？

按顺序查四件事——面板映射是否保存、小鸡内服务是否监听、本机防火墙是否放行、商家是否限制了该端口或协议。用 ss -tlnp 和外部 nc -vz 对照排查最快。

NAT VPS 能跑 Docker 吗？

KVM 通常可以；LXC/OpenVZ 需要商家开启嵌套能力，很多低价套餐不支持。下单前看产品说明或开工单确认，不要默认可以。

IPv6 能绕过端口限制吗？

能。给域名配 AAAA 记录，支持 IPv6 的访客可以直达，不受 IPv4 端口映射数量限制；但只有 IPv4 的访客仍需回退方案。

共享 IP 会影响 SEO 或支付风控吗？

可能。IP 信誉由所有使用者共同影响，搜索引擎和风控系统可能参考 IP 历史，无法保证不受影响。重要业务建议独立 IP、自有域名和稳定主体信息。

端口或 IP 会变吗？商家跑路怎么办？

部分商家会调整共享 IP 或端口分配，需用 DDNS 和面板核对；小商家存在经营风险，重要数据务必异地备份，只把可重建的服务放在上面。
