从 0 搭家庭实验室（Homelab）：一台便宜 VPS 能玩出什么花？2026 完整路线图

2026-07-24动态实时复核有效5632 字15 分钟阅读
本篇评测核心结论与选购速览依据与适用条件见正文

家庭实验室不是大佬的玩具。一台年付十几美元的 VPS，加上 Docker Compose 和 Cloudflare Tunnel，就能把密码库、网盘、笔记、监控、Git、影音、文档扫描全部收回自己手里。本文给出 10 个值得长期跑的自托管服务、一台 1C1G 能跑几个容器的真实数据、完整搭建步骤与 30 天路线。

⚠️ 重要声明与免责提示：
本文内容及测评数据均来源于网络（由玩家及社区公开分享，参考来源包括 NodeSeek 社区实测 与 LowEndTalk 讨论）。鉴于跨境路由与各机房突发带宽策略随时变动，本文信息可能已经过时，请以各商家的实时线路和性能为准。

「家庭实验室（Homelab）」听起来像是有钱有闲的技术大佬才玩的东西：机柜、万兆交换机、一堆 NAS 硬盘。但如果你只是想把数据主权拿回来，一台年付十几美元的 VPS 就够了——它能跑的东西，比大多数人想象的多得多。

这篇文章不讲玄学，只讲三件事：一台便宜 VPS 到底能跑什么、需要多少资源、怎么从 0 搭起来并且不把自己坑死。所有命令和配置都可以直接复制，所有资源数据都给出实测区间。

一、先想清楚：你要的 Homelab 是哪一种

「Homelab」在中文语境里其实混了两种完全不同的东西，先分清楚，能省下不少钱。

类型硬件优势劣势适合谁
家宽 NAS 型家里放一台 NAS / 迷你主机硬盘大、内网速度快、数据物理在自己手里公网 IP 难搞、停电断网就挂、噪音与电费影音库、照片备份、智能家居
云上 VPS 型一台年付 $15–$60 的 VPS7×24 在线、有公网 IP、异地容灾、随时可迁移磁盘小（20–80GB）、内存有限（1–4GB）密码库、笔记、监控、Git、轻量网盘、博客
混合型VPS 做入口 + NAS 做存储兼顾公网访问与大容量架构复杂，需要组网进阶玩家

本文讲的是云上 VPS 型。它的核心价值不是「省钱」，而是「7×24 在线 + 有公网地址 + 数据不放在别人家」。如果你要存几 TB 的影视资源，别用 VPS，买 NAS；如果你要的是「随时能访问、随时能同步、随时能备份」，VPS 是更划算的选择。

预算参考：1 核 1GB / 20GB 的年付机型，$15–$50/年就能拿下（RackNerd、CloudCone、ColoCrossing 这个档位都有）。跑本文的全部服务绰绰有余。

二、你需要什么配置：一张真实的内存账单

新手最常问的问题是「1GB 内存够不够」。答案是：取决于你跑多少个容器、每个容器多胖。下面是常见自托管服务的实测内存区间（Debian 12 + Docker，空闲状态）：

服务用途内存占用磁盘占用
Docker 引擎本身容器运行时80–150MB~1GB
Caddy / Nginx反向代理 + 自动 HTTPS30–60MB~50MB
VaultwardenBitwarden 兼容密码库30–80MB~200MB
Uptime Kuma服务监控 + 告警80–150MB~500MB
Gitea自建 Git 服务100–200MB~1GB
Trilium / Memos自托管笔记50–120MB~300MB
Syncthing多端文件同步60–120MB~200MB
Nextcloud网盘（含 PHP + DB）300–600MB~2GB
Immich照片备份（含 ML 服务）800MB–2GB~3GB
Paperless-ngx文档扫描与 OCR400MB–1GB~1GB
Jellyfin影音串流200–500MB（转码另算）~500MB

按这张表算：

  • 1GB 内存：能跑「反代 + Vaultwarden + Uptime Kuma + Trilium」，大约 4 个轻量服务，剩余 200MB 左右缓冲；
  • 2GB 内存：加上 Gitea、Syncthing、Nextcloud，大约 7 个服务，是最舒服的甜点；
  • 4GB 内存：可以上 Immich、Paperless-ngx，做「全家桶」；
  • 8GB 以上：跑 Jellyfin 转码、本地大模型推理，但这时候 VPS 的性价比已经不如家里放一台机器。

结论：新手直接买 2GB 内存的机型。1GB 会不断让你在「要不要删掉某个服务」之间纠结，省下的十几美元不值得。

三、整体架构：四层就够了

一个能长期维护的 Homelab，架构应该简单到「三个月不碰也能想起来」。推荐四层：

SHELL / COMMAND 
用户浏览器
   │ HTTPS
   ▼
Cloudflare（DNS + CDN + WAF）
   │ 加密隧道（cloudflared 主动外连，无需开放入站端口）
   ▼
Caddy 反向代理（:80 / :443，自动证书）
   │ 内网 HTTP
   ├── Vaultwarden  :8080
   ├── Uptime Kuma  :3001
   ├── Gitea        :3000
   └── 其他容器...
        │
        ▼
   数据卷（/srv/data/...）+ 定时备份到对象存储

每一层的职责：

  1. Cloudflare：DNS 解析、隐藏源站 IP、基础 WAF、缓存静态资源。免费计划就够。
  2. cloudflared：从服务器主动向外建立加密隧道，外部流量经 Cloudflare 网络回源到本机。好处是不需要开放任何入站端口，扫描器扫不到你。
  3. Caddy：把不同域名分发到不同容器，自动申请与续期证书。配置文件只有几行。
  4. Docker Compose：每个服务一个目录、一个 compose.yaml，数据统一挂在 /srv/data 下。

这套架构的关键是「源站不暴露」：即使有人知道你的 VPS IP，也打不开任何服务，因为 80/443 只允许 Cloudflare 回源 IP 访问（或者根本只监听 localhost）。

四、十个值得长期跑的自托管服务

下面这十个服务，是社区里「装了之后会一直用」的典型。选 3–5 个开始，别一次全上。

1. Vaultwarden —— 密码库（必装）

Bitwarden 的轻量 Rust 实现，兼容官方客户端，内存占用只有几十 MB。装好之后，手机、浏览器、桌面端全部同步，再也不用记「这个网站的密码是哪个变体」。

DOCKER 
services:
  vaultwarden:
    image: vaultwarden/server:latest
    restart: unless-stopped
    environment:
      DOMAIN: https://vault.example.com
      SIGNUPS_ALLOWED: "false"   # 注册完第一个账号后关掉
    volumes:
      - /srv/data/vaultwarden:/data

注意：密码库是「丢了就完蛋」的数据，必须做异地备份，并且把主密码写进物理保险柜。不要只依赖 VPS 快照。

2. Uptime Kuma —— 服务监控（必装）

「服务挂了没人知道」是自托管最大的坑。Uptime Kuma 支持 HTTP / TCP / Ping / DNS / Docker 容器监控，挂了可以推 Telegram、邮件、Webhook。界面好看，中文完整。

DOCKER 
services:
  uptime-kuma:
    image: louislam/uptime-kuma:1
    restart: unless-stopped
    ports:
      - "127.0.0.1:3001:3001"
    volumes:
      - /srv/data/uptime-kuma:/app/data

3. Gitea —— 自建 Git（推荐）

轻量级 Git 服务，支持 Issue、PR、Actions、包管理。适合放私有仓库、dotfiles、博客源码。1GB 内存也能跑得很顺。

4. Trilium / Memos / Outline —— 笔记

  • Trilium：树形笔记，支持关系图，适合知识库；
  • Memos：极简「碎片笔记」，像自建的 Flomo，一条命令就能跑；
  • Outline：团队协作文档，需要 PostgreSQL + Redis + S3，重一些但体验最好。

5. Syncthing —— 多端文件同步

点对点同步，不经过第三方服务器。手机照片、电脑文档、服务器配置可以互相同步。配合 VPS 做「中转节点」，即使两台设备不同时在线也能同步。

6. Nextcloud —— 网盘

老牌自托管网盘，支持 WebDAV、客户端同步、在线 Office（配合 Collabora）。资源占用偏高（PHP + 数据库），2GB 内存起步。

7. Immich —— 照片备份（重）

Google Photos 的开源替代，支持人脸识别、EXIF 搜索、相册共享、手机自动备份。需要 PostgreSQL + Redis + 机器学习容器，4GB 内存起步，但体验是目前最好的。

8. Paperless-ngx —— 文档扫描与 OCR

把纸质文件拍照/扫描后自动 OCR、自动分类、全文搜索。适合整理发票、合同、证件。需要 Redis + 数据库，内存 1GB 起。

9. Jellyfin —— 影音串流

开源媒体服务器，支持硬件转码。VPS 上跑要注意：带宽和 CPU 是瓶颈，直连播放没问题，转码会吃满 CPU。更适合放在家里的 NAS 上。

10. Home Assistant —— 智能家居

把米家、HomeKit、涂鸦等设备统一管理，做自动化。放 VPS 上的问题是「需要和家里设备在同一网络」，通常要配合 Tailscale 或家里再放一个节点。

五、从零搭建：30 分钟跑起第一个服务

第 1 步：系统准备

SYSTEMD 
# 更新系统
apt update && apt upgrade -y

# 安装 Docker（官方脚本）
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 安装 Compose 插件
apt install -y docker-compose-plugin

# 验证
docker --version && docker compose version

第 2 步：建目录规范

这是「三个月后还能维护」的关键。推荐结构：

SHELL / COMMAND 
/srv/
├── data/                 # 所有持久化数据
│   ├── vaultwarden/
│   ├── uptime-kuma/
│   └── gitea/
├── stacks/               # 每个服务的 compose 文件
│   ├── vaultwarden/compose.yaml
│   ├── uptime-kuma/compose.yaml
│   └── caddy/compose.yaml
└── backup/               # 本地临时备份

第 3 步：Caddy 反向代理

DOCKER 
# /srv/stacks/caddy/compose.yaml
services:
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - /srv/data/caddy:/data
      - /srv/data/caddy/config:/config
SHELL / COMMAND 
# /srv/stacks/caddy/Caddyfile
vault.example.com {
    reverse_proxy 127.0.0.1:8080
}
status.example.com {
    reverse_proxy 127.0.0.1:3001
}
git.example.com {
    reverse_proxy 127.0.0.1:3000
}

Caddy 会自动申请 Let's Encrypt 证书并续期，不需要额外配置。

第 4 步：Cloudflare Tunnel（不想暴露 IP 时）

SYSTEMD 
# 安装 cloudflared
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg |   sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main" |   sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update && sudo apt install -y cloudflared

# 登录并创建隧道（会给出一个 token）
cloudflared tunnel login
cloudflared tunnel create homelab

# 配置 /etc/cloudflared/config.yml
# tunnel: <你的隧道ID>
# credentials-file: /root/.cloudflared/<隧道ID>.json
# ingress:
#   - hostname: vault.example.com
#     service: http://localhost:8080
#   - service: http_status:404

# 绑定域名并启动
cloudflared tunnel route dns homelab vault.example.com
sudo cloudflared service install
sudo systemctl enable --now cloudflared

配好之后，源站的 80/443 可以完全关闭，所有流量都从 Cloudflare 的隧道进来。这一步能把「被扫描、被爆破」的概率降到接近零。

第 5 步：加一层身份验证

Cloudflare Access 可以给域名加「邮箱验证码 / Google 登录 / GitHub 登录」的门槛，免费计划支持 50 个用户。配置路径：Zero Trust → Access → Applications → Add an application → Self-hosted。

这一步的意义是：即使密码泄漏，攻击者也进不来。对于自托管的敏感服务（密码库、Git、文档），强烈建议开启。

六、安全：别让自己成为肉鸡

自托管最常见的翻车方式不是「被黑客高级攻击」，而是「某个容器有未修复的漏洞 + 暴露在公网 + 没人更新」。做好下面五件事，能挡掉 99% 的风险：

  1. 不暴露源站 IP：用 Cloudflare Tunnel 或只允许 CF 回源 IP 访问；
  2. 容器不用 root 跑：Compose 里加 user: "1000:1000"，镜像没有非 root 用户时自己建；
  3. 镜像固定版本：不要用 :latest，用具体 tag（如 :1.32），升级前先看 changelog；
  4. 自动更新 + 定期看日志：可以用 Watchtower 自动拉取，但生产环境建议手动确认；
  5. 给容器限资源：mem_limit、cpus，防止一个服务吃光内存把整台机器拖死。
DOCKER 
services:
  app:
    image: example/app:1.2.3
    user: "1000:1000"
    mem_limit: 512m
    cpus: 1.0
    read_only: true
    tmpfs:
      - /tmp
    security_opt:
      - no-new-privileges:true

七、备份：Homelab 的生死线

自托管最大的风险不是「服务挂了」，而是「数据丢了」。一个可执行的备份方案应该满足三点：自动、异地、可恢复。

1. 备份什么

  • /srv/data：所有容器的持久化数据；
  • /srv/stacks：所有 compose 与配置文件（这个最容易被忘）；
  • 数据库导出：PostgreSQL 用 pg_dump，MySQL 用 mysqldump，不要直接拷贝数据目录；
  • 系统级的 crontab、systemd unit、SSH 配置。

2. 备份到哪

推荐「本地 + 对象存储」双份：本地用 restic 做增量快照，对象存储用 Cloudflare R2（10GB 免费）或 Backblaze B2（$6/TB/月）。

SHELL / COMMAND 
# 初始化 restic 仓库
export RESTIC_REPOSITORY="s3:https://<account>.r2.cloudflarestorage.com/backup"
export RESTIC_PASSWORD="<强密码>"
restic init

# 每天备份
restic backup /srv/data /srv/stacks --exclude="*.log"

# 保留策略：最近 7 天、4 周、6 个月
restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune

3. 一定要演练恢复

没恢复过的备份等于没有备份。每季度做一次演练：把备份恢复到临时目录，起一个容器，确认数据完整。这一步花 30 分钟，能救命。

九、十个常见坑

  1. 端口冲突：两个容器都想用 8080，第二个起不来。统一用 127.0.0.1:端口:容器端口，端口规划写进文档；
  2. 权限问题：容器写入挂载目录报 Permission denied，用 id 查宿主机用户 UID，再在 compose 里对齐；
  3. 内存溢出：1GB 机器上跑 Immich，OOM Killer 会随机杀进程。加 swap 或 mem_limit；
  4. 磁盘写满：Docker 日志默认无限增长，在 /etc/docker/daemon.json 里配 log-opts 限制大小；
  5. 时区不对：容器默认 UTC，加 TZ=Asia/Shanghai 环境变量；
  6. 数据库版本升级：PostgreSQL 大版本不能直接升级，必须 pg_dump 导出再导入；
  7. 反向代理的 WebSocket：Uptime Kuma、Gitea 需要 WebSocket，Caddy / Nginx 要额外配置 Upgrade 头；
  8. 备份没排除缓存：把 node_modules、cache 也备份了，仓库迅速膨胀；
  9. 忘记改默认密码：很多镜像默认 admin/admin，暴露公网等于送人头；
  10. 只在一个机房：VPS 商跑路或机房故障，服务全挂。重要数据一定要有异地副本。

十二、进阶：多机组网与远程访问

当你的 Homelab 从「一台 VPS」变成「VPS + 家里的 NAS + 公司电脑」时，会遇到一个新问题：怎么让这三台机器像在同一个局域网里一样互相访问？这就是「组网」要解决的事。

1. 三种组网方案对比

方案原理上手难度适合场景坑
Tailscale基于 WireGuard 的 mesh 网络，自动 NAT 穿透极低（客户端安装即用）个人多设备、远程访问 NAS免费版限 3 用户 / 100 设备
ZeroTier自建虚拟二层网络低需要二层广播（如局域网游戏、旧设备发现）免费版限 25 设备，国内延迟看 Planet 节点
WireGuard 自建自己搭 VPN 服务端中高对隐私与可控性要求高需要公网 IP、需自己维护密钥与路由

绝大多数人用 Tailscale 就够：它把「NAT 穿透」这件麻烦事全包了，你在 VPS、NAS、手机、笔记本上各装一个客户端，登录同一个账号，它们就自动组成一个虚拟局域网，每台机器有一个 100.x.x.x 的内网 IP。

2. 典型用法：用 Tailscale 把 NAS 接到 VPS 后面

假设你的服务跑在家里的 NAS 上，但家里没有公网 IP。可以这样做：

  1. 在 VPS 和 NAS 上都安装 Tailscale 并登录同一账号；
  2. 在 VPS 上用 tailscale status 拿到 NAS 的虚拟 IP（如 100.64.0.5）；
  3. 在 Caddy 里把域名反代到 http://100.64.0.5:8080；
  4. Cloudflare Tunnel 指向 Caddy，外部访问就通了。

这样 NAS 不需要公网 IP、不需要开端口，所有流量走 Tailscale 的加密隧道。代价是多了一跳加密解密，延迟会增加 5–20ms（取决于中继节点）。

3. 一个容易忽略的细节：DNS

Tailscale 支持「MagicDNS」，给每台设备分配一个 设备名.tailnet-name.ts.net 的域名。这在你写配置时特别有用——比记 IP 靠谱，换设备也不用改配置。

但要注意：MagicDNS 只在 Tailscale 客户端里生效。如果你的 Caddy 跑在 VPS 上，而 VPS 本身不在 Tailscale 网络里（比如你用 Docker 隔离了网络），ping nas 会解析失败。解决办法是把 Caddy 容器接入 host 网络，或者改用虚拟 IP。

如果你就想花最少的钱跑起来，下面这份清单经过实测，在 1 核 1GB / 20GB 磁盘的机器上稳定运行（Debian 12 + Docker）：

一份可直接用的 compose 片段

DOCKER 
name: homelab

networks:
  web:
    driver: bridge

services:
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - /srv/data/caddy:/data
    mem_limit: 128m

  vaultwarden:
    image: vaultwarden/server:1.32.7
    restart: unless-stopped
    environment:
      DOMAIN: https://vault.example.com
      SIGNUPS_ALLOWED: "false"
      TZ: Asia/Shanghai
    volumes:
      - /srv/data/vaultwarden:/data
    ports:
      - "127.0.0.1:8080:80"
    mem_limit: 128m

  uptime-kuma:
    image: louislam/uptime-kuma:1.23.16
    restart: unless-stopped
    environment:
      TZ: Asia/Shanghai
    volumes:
      - /srv/data/uptime-kuma:/app/data
    ports:
      - "127.0.0.1:3001:3001"
    mem_limit: 256m

注意两个细节：

  • 端口绑定写 127.0.0.1，不要写 0.0.0.0。这样即使防火墙配错，外部也扫不到；
  • 镜像用具体版本号，不用 :latest。升级时改版本号 + docker compose up -d，回滚只需改回去。

十四、什么时候该从 VPS 迁到 NAS

VPS 不是终点。当下面这些信号出现时，说明你该考虑「家里放一台机器」了：

  1. 存储不够用：照片和文档超过 50GB，VPS 的磁盘升级价格远高于买硬盘；
  2. 需要转码：Jellyfin 在 VPS 上转码会吃满 CPU，而家用 NAS 的核显可以硬解；
  3. 内网速度要求高：4K 视频剪辑、虚拟机磁盘、大量小文件同步，千兆内网比公网快一个数量级；
  4. 数据敏感度高：医疗、财务、家庭照片，放在自己家的硬盘上心理负担更小；
  5. VPS 商频繁被攻击 / 跑路风险：小厂 VPS 的稳定性不如自己家的电和网。

迁移路径建议：VPS 保留作为「入口 + 监控 + 备份」，把存储与计算挪到 NAS。这样公网访问由 VPS 的 Cloudflare Tunnel 承担，数据在自己家，两边各司其职。

硬件选择上，不用追求「全新企业级」：二手的迷你主机（N100 / J4125 / 老款 NUC）+ 一块 SSD，一千多块就能搭一台够用的 NAS，功耗 10W 左右，一年电费不到 100 块。

十六、小内存调优：让 1GB 跑出 2GB 的效果

如果你已经买了 1GB 的机器，别急着退货。下面四项调整能把可用内存抬高三到五成：

1. 开 zram（内存压缩交换）

SYSTEMD 
apt install -y zram-tools
# 编辑 /etc/default/zramswap
# ALGO=zstd
# PERCENT=50
systemctl restart zramswap
swapon --show

zram 用 CPU 换内存，压缩比通常在 2:1 到 3:1。对 1GB 机器来说，等于多出 500MB 内存，代价是少量 CPU 开销。

2. 限制 Docker 日志

SYSTEMD 
# /etc/docker/daemon.json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}

systemctl restart docker

默认的 json-file 驱动会无限增长，一个刷屏的服务能在几天内写满磁盘。

3. 关掉不用的 systemd 服务

SYSTEMD 
systemctl list-unit-files --state=enabled
# 常见可关： snapd、ModemManager、bluetooth、cups、avahi-daemon
systemctl disable --now snapd.socket snapd

一个干净的 Debian 12 最小安装，空闲内存约 120MB；开了 snapd、云厂商 agent、监控后可能到 300MB。关掉用不到的，能省下 100–200MB。

4. 给容器设内存上限

没有上限的容器会在内存紧张时被 OOM Killer 随机杀，而不是「自己失败」。加上 mem_limit 后，超限的容器会被单独杀死并重启，不会拖死整台机器。

SHELL / COMMAND 
docker stats --no-stream    # 看每个容器的实时占用
cat /sys/fs/cgroup/memory.max   # 看 cgroup 限额

常见热点问题解答 (FAQ)

1 核 1GB 的机器真的够吗？

够跑 4 个左右轻量服务（反代 + 密码库 + 监控 + 笔记）。想上 Nextcloud 或 Immich，建议直接 2GB 起。

必须用 Cloudflare 吗？

不是必须，但强烈建议。它同时解决「隐藏源站 IP」「免费 HTTPS」「基础 WAF」「内网穿透」四件事，自建替代方案要花好几倍时间。

VPS 商跑路了怎么办？

选经营三年以上、口碑稳定的商家；同时保持「数据可迁移」——所有配置用 compose 管理，数据在 /srv/data，换机器时 rsync 过去就能跑。

需要备案吗？

如果域名解析到大陆服务器并提供网站服务，需要 ICP 备案；境外 VPS 不需要备案，但访问速度和稳定性受国际带宽影响。

Docker 还是直接装？

自托管场景优先 Docker：升级、回滚、迁移都简单。除非你要榨干最后一点性能，否则没必要裸装。

会不会被服务商封号？

正常自用不会。但不要跑公开代理、爬虫、PT 站、盗版影音分发，这些违反绝大多数 TOS。

需要学多久？

会基本的 Linux 命令（cd/ls/vim/systemctl）就能开始，大约一周能跑通第一套。剩下的都是在解决问题中学会的。

手机端怎么访问？

Vaultwarden、Nextcloud、Immich 都有官方 App；其他服务可以用浏览器添加到主屏幕（PWA），体验接近原生。

监控自己会不会很吃资源？

Uptime Kuma 监控 20 个目标大约占 100MB 内存。如果只监控几个站点，也可以用 Cloudflare 自带的 Health Check（免费）。
