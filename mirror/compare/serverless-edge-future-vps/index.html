VPS 会被淘汰吗？从 AWS Lambda 到 Cloudflare Workers 的算力变革

2026-08-14动态实时复核有效2347 字7 分钟阅读
本篇评测核心结论与选购速览依据与适用条件见正文

无服务器不是没有服务器，而是你不用管服务器。AWS Lambda 2014 年发布，百万次调用只要 0.2 美元；Cloudflare Workers 把代码部署到全球 330 多个城市，每天 10 万次免费。它会淘汰 VPS 吗？冷启动、锁定风险、长连接、数据库……一张对照表和决策清单，说清什么项目继续用便宜 VPS、什么该上 Serverless。

先讲个故事。2014 年 11 月，亚马逊在拉斯维加斯的年度开发者大会上发布了一个叫 AWS Lambda 的新服务，台下响起一片尖叫。这个服务干了一件在当时看起来很"反人类"的事：你只需要交一段代码，连服务器都不用买，这段代码会在"被调用"的那一刻凭空启动，跑完立刻消失。用云厂商的话说，这叫"无服务器"（Serverless）。当时没人想到，这个"用完即毁"的小函数，会在之后十年里，让"买台 VPS 挂着跑"这个延续了二十年的习惯，第一次真正受到了挑战。

作为常年混迹在便宜 VPS 圈子里的人，你可能更关心这个问题：我花 20 美元一年买的机器，会被这些新玩意淘汰吗？这篇文章就用大白话把 Serverless、边缘计算这些词拆开揉碎，讲清楚它们跟 VPS 到底谁该被淘汰，以及你该在什么场景下把钱花给谁。

无服务器到底是什么？——不是没有服务器，是你不用管

先破除一个最大的误解："Serverless"不是说世界上没有服务器了。恰恰相反，它背后跑着几千台服务器，只是这些服务器跟你没关系了。

打个比方。传统 VPS 就像租了一间公寓：押一付三、自己交水电、灯泡坏了得自己换。而 Serverless 更像打车：按里程付费，车到了上车，到站下车，方向盘、加油、保养全是司机的事。再换个说法，它像你家楼下 24 小时的便利店——不用在家囤一冰箱食材，想喝可乐随时下楼买一瓶，按瓶算钱。

具体到技术上：你写好一个函数（比如"用户上传图片后自动生成缩略图"），扔到云上，剩下的事全自动。平时没人调用，它就不运行、不花一分钱；突然来一千个请求，平台自动给你复制出一千个实例同时干活；流量过去，它又缩回零。按量计费、用完即毁、自动伸缩——这就是 Serverless 的三大核心特征。

顺带说个当年发布时的细节：Lambda 刚出来时定价是每 100 万次请求 0.2 美元，折算下来单次调用基本等于不要钱。这个"按量计价"的逻辑，后来成了整个行业的样板，也埋下了它跟"包月制"VPS 之间最根本的分歧。

两大代表：AWS Lambda 和 Cloudflare Workers

Serverless 发展十年，格局基本被两股势力瓜分：一个是"老牌正规军"AWS Lambda，一个是"边缘奇兵"Cloudflare Workers。

Lambda 是祖师爷，2014 年发布、2015 年正式商用。它深度绑定 AWS 生态：S3 里传个文件、数据库里加条记录、HTTP 请求进来，都能触发你的函数。价格便宜到离谱——每月前 100 万次请求免费，超出后每 100 万次收 0.2 美元；你一个月跑 300 万次调用，请求费才 0.4 美元。当然它也有脾气：单个函数最长只能跑 15 分钟；第一次调用要等几百毫秒甚至一两秒（这就是著名的"冷启动"问题）；而且代码一旦用了 AWS 特有的接口，想搬去别家就难了。

Cloudflare Workers 则是 2017 年杀出来的搅局者。它不打"数据中心"牌，打"边缘"牌：代码直接部署到 Cloudflare 在全球 330 多个城市的机房节点上，哪个城市的用户来访问，就在哪个城市执行——物理距离最短，延迟自然最低。它跑在 Chrome 同款 V8 引擎的"沙箱"里，冷启动不到 5 毫秒，几乎感觉不到。免费额度也大方得不像话：每天 10 万次请求免费，个人站根本用不完；付费版 5 美元一个月含 1000 万次请求，超出部分每百万次才 0.3 美元。毕竟 Cloudflare 的骨干网承载着全球大约两成互联网流量，机房本来就在那里，顺路就把你的代码也跑了。

顺带解释一下"边缘计算"这个词。传统云计算把服务器集中在弗吉尼亚、新加坡这类大型机房，你在国内访问可能要绕半个地球；边缘计算反着来，把算力"摊"到离用户最近的几百个机房。可以理解成把厨子从中央厨房派到每个小区门口，饭菜出锅就能端上桌。光速是物理极限，距离越近延迟越低，这是边缘计算最朴素也最硬核的道理。

Serverless 怎么改变我们写网站？

这些年如果你写前端，应该已经感受到变化了。以前搭一个网站，要么买台 VPS 自己配 Nginx 跑 PHP 或 Node，要么用虚拟主机；现在用 Vercel、Netlify 这类平台，静态页面加一堆"函数"一整套丢上去，全世界自动分发，Git 推一次就部署一次。Next.js 这种框架甚至让前端直接写全栈——页面是静态的，接口是函数，全程不用碰服务器。

更常见的是把零碎功能做成函数：

  • 图片处理：用户上传原图，自动压缩、生成多尺寸缩略图。
  • API 网关：鉴权、限流、转发，请求先过一道函数。
  • A/B 测试：同一个 URL，按用户分流返回不同版本。
  • 防盗链、防爬：在边缘直接拦截，不浪费源站一毛钱流量。
  • Webhook 接收器：第三方服务发回调，函数收下处理完拉倒。

这些活的特点是：偶尔来一下、一次就几秒钟、不处理也行但处理了体验更好。放 VPS 上你得为它常年开机，放 Serverless 上则是一分钱不跑不花。

VPS vs Serverless，一张对照表

吹了这么多，也该泼泼冷水了。Serverless 不是银弹，它跟 VPS 是两种完全不同的物种，各有各的毛病。把账摊开算：

  • 成本：VPS 是包月包年，哪怕闲置 99% 的时间也全额付费；Serverless 按量计费，闲置即零成本。但反过来，一旦流量稳定且不小，VPS 立刻反超——一个月 3000 万次调用，Lambda 大约要花 30 美元，而一台 4 核 VPS 也就 16 美元左右。
  • 冷启动：VPS 上的服务常驻内存，响应稳定；Serverless 首次调用要现场启动函数，可能白等 1 到 2 秒。对延迟敏感的接口，这是致命的。
  • 长连接：WebSocket、游戏、实时聊天这些要长期保持连接的场景，和"用完即毁"的函数天生不对付。
  • 数据库：VPS 上装 MySQL、PostgreSQL 随便折腾；Serverless 没有自己的硬盘，要么接云数据库（要花钱），要么另想办法。
  • 可移植性：VPS 上跑的是标准 Linux，换任何一家都能迁；Serverless 的代码深度绑定平台，AWS 的函数搬到 Cloudflare 基本等于重写。
  • 运维：VPS 要自己打补丁、防攻击、搞备份；Serverless 平台全包了，你只写代码。

一句话总结：VPS 像买房——前期贵、常年养着，但住得踏实、想怎么折腾怎么折腾；Serverless 像打车——用一次付一次，轻快灵活，但你不能在车上过日子。

VPS 会被淘汰吗？

结论先放这儿：短期内不会，而且永远有一席之地。VPS 在下面这些场景里依然不可替代：

  • 要长期跑的守护进程：监控机器人、爬虫、下载机，7 乘 24 小时在线，函数模型跑不了。
  • 要 root 权限：改内核参数、装特殊软件、配防火墙，函数给不了你。
  • 要跑 Docker 和数据库：一套 Docker Compose 把 Nginx、Redis、PostgreSQL 编排起来，这是 VPS 的主场。
  • 价格敏感的长驻服务：一台年付 15 到 20 美元的 VPS 挂个小站，比任何按量计费都划算。
  • 学习 Linux：想真的搞懂服务器是怎么运转的，你得先有一台自己的机器。

反过来，流量忽高忽低、调用频率低、想快速验证想法的新项目，直接上 Serverless 更香。聪明人的玩法从来不是二选一，而是混搭：VPS 上跑核心服务和数据库，把图片处理、Webhook、定时任务这类"零碎活"外包给函数——固定的成本稳住基本盘，弹性的部分按量买单。

给小站长和开发者的最终建议

落到钱包上，我的建议就三条。第一，如果你的项目是"常驻型"的——网站、机器人、API、数据库，那就继续用便宜年付 VPS，别犹豫，RackNerd 这类商家 20 美元一年的机器，对绝大多数个人项目来说是性价比之王。第二，如果你在写一个流量不确定的新应用，或者有很多"偶发"的零碎任务，用 Cloudflare Workers 或 Vercel Functions 先跑起来，每月成本从 0 开始。第三，学会组合：主体用 VPS 兜底，边缘用函数补位。技术选型没有标准答案，只有"哪个更省心、更省钱"的权衡——记住这句话，你就不会在任何一场技术争论里被带偏。
