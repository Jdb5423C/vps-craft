VPS 离线下载实战：Aria2 + qBittorrent 把服务器当下载机

把 VPS 变成离线下载机的完整流程：Aria2 + AriaNg 与 qBittorrent-nox 两条路线的安装、systemd 常驻、RPC token 与反代 HTTPS 加固、磁盘与带宽规划、BT 做种的版权与商家 AUP 风险，以及和网盘、对象存储的配合方式。命令标注为测试环境示例。

⚠️ 重要声明与免责提示：
本文内容及测评数据均来源于网络（由玩家及社区公开分享，参考来源包括 NodeSeek 社区实测 与 LowEndTalk 讨论）。鉴于跨境路由与各机房突发带宽策略随时变动，本文信息可能已经过时，请以各商家的实时线路和性能为准。

把 VPS 当下载机，是很多人买下第一台小鸡之后最想做的事：白天在公司丢一个磁力链接进去，晚上回家文件已经躺在网盘里。这件事听起来简单，真正动手时却常常卡在三个地方——RPC 端口默认对全网开放、systemd 服务一重启任务全丢、以及把 BT 流量跑在共享 IP 上被商家投诉。这篇把 Aria2 + AriaNg 和 qBittorrent-nox 两条路线从头到尾走一遍，重点不在于「怎么装」，而在于「装完之后怎么不被扫、不被封、不把盘写坏」。

说明：下文所有命令均按 Debian / Ubuntu 系发行版的官方文档与上游手册整理，并在段落中标注为「测试环境示例」。端口、路径、软件包名在不同发行版上可能不同，以你的发行版为准。本文不声称是本站生产环境的实测结果，也不构成版权或合规意见；具体条款请以你与商家签订的 AUP 及当地法律为准。

一、先想清楚：VPS 下载机到底解决什么问题

离线下载的核心价值不是「下载」，而是把「等待」从你的设备上挪走。家庭宽带的上行通常只有几十兆，做种几乎不可能；电脑关机、笔记本合盖、手机切后台，任务就断了。而一台 7×24 在机房的 VPS，恰好具备三个条件：持续在线的公网 IP、稳定的对称带宽、以及可以随便折腾的 root 权限。

但要先摆正预期。绝大多数入门 VPS 的「1 Gbps 端口」是共享口，晚高峰实际能跑多少取决于同机房邻居；流量包也常常是每月 1 TB 到 3 TB 的量级。用它拉几个 Linux 镜像、几部开源纪录片、一堆模型权重，非常合适；想拿它当 24 小时满速 PT 盒子，就要先算清楚流量账，否则月底不是被限速就是被停机。

另一个容易被忽略的点是数据归属。下载机上的文件留在商家机房，磁盘由商家物理接触。涉及个人隐私、公司资料、未公开素材的内容，不要放在租来的机器上。这条比任何技术细节都重要。

二、两条路线：Aria2 + AriaNg 还是 qBittorrent-nox

这两个东西经常被放在一起比较，但它们其实不是同类产品。Aria2 是一个多协议的命令行下载器，本身没有界面，靠 JSON-RPC 对外提供控制接口；AriaNg 是纯静态的网页前端，只负责把 RPC 包装成可点的按钮。qBittorrent-nox 则是一个完整的、去掉图形界面的 BT 客户端，WebUI 是它自己内置的。

维度Aria2 + AriaNgqBittorrent-nox
运行形态命令行守护进程 + 一份纯 HTML/JS 静态页无 GUI 的完整 BT 客户端，WebUI 内置
协议覆盖HTTP(S)、FTP、SFTP、BitTorrent、Metalink以 BitTorrent 为主
HTTP 多线程下载支持，可对同一文件开多连接（split）不支持，仅按 BT 分片调度
内存占用官方口径：普通 HTTP 约 4 MiB，BT 约 9 MiB数十 MB 起，队列与连接数越大越高
鉴权方式JSON-RPC 的 rpc-secret tokenWebUI 账号密码，可选 IP 白名单
更适合直链、镜像、临时批量任务长期做种、RSS 订阅、分类与限速策略

一句话建议：主要拉直链和镜像就用 Aria2，主要玩 BT 做种就用 qBittorrent-nox。两者可以共存，但 1 GB 内存以下的小机器不建议同时开——它们都会各自维护一份 DHT 路由表与连接池，叠加之后的文件描述符和内存开销很容易把 swap 打满。

三、Aria2 安装与最小可用配置

下面以 Debian 12 / Ubuntu 22.04 为参照，测试环境示例。软件包在 Debian 与 Ubuntu 的官方源里都叫 aria2，RHEL 系在 EPEL 里，包名与路径以你的发行版为准。

SHELL / COMMAND 
sudo apt update
sudo apt install -y aria2
aria2c --version

装完之后不要急着开 RPC。先建一个专用系统用户和独立的数据目录，让下载进程以最小权限运行，这样即使 RPC 被攻破，攻击者也拿不到 root：

SHELL / COMMAND 
sudo useradd --system --create-home --shell /usr/sbin/nologin aria2
sudo mkdir -p /etc/aria2 /srv/downloads
sudo chown -R aria2:aria2 /etc/aria2 /srv/downloads
sudo -u aria2 truncate -s 0 /etc/aria2/aria2.session

然后是配置文件。注意 rpc-secret 一定要换成你自己生成的长随机串，下面这行只是占位。生成方式见后面的命令。

SHELL / COMMAND 
# /etc/aria2/aria2.conf  —— 测试环境示例，参数以官方手册为准
enable-rpc=true
rpc-listen-all=false
rpc-listen-port=6800
rpc-allow-origin-all=false
rpc-secret=REPLACE_WITH_YOUR_OWN_TOKEN

dir=/srv/downloads
continue=true
max-concurrent-downloads=5
max-connection-per-server=8
split=8
min-split-size=1M
file-allocation=falloc
disk-cache=64M

input-file=/etc/aria2/aria2.session
save-session=/etc/aria2/aria2.session
save-session-interval=60

enable-dht=true
bt-enable-lpd=true
bt-max-peers=64
seed-ratio=1.0

几个参数值得单独解释。save-session 与 input-file 指向同一个文件，是让重启后能续上队列的关键，少了它，systemd 一重启你昨天排的队就全没了。file-allocation 在 ext4 上建议 falloc，xfs 上可以用默认值，机械盘上 prealloc 会明显更慢。seed-ratio=1.0 表示分享率达到 1.0 就停止做种，这是控制上传流量最省心的一个开关，具体数值按你的带宽和 AUP 调整。

生成 token 并写入配置，顺便把权限收紧到只有 aria2 用户能读：

SHELL / COMMAND 
TOKEN=$(openssl rand -hex 32)
sudo -u aria2 sed -i "s/REPLACE_WITH_YOUR_OWN_TOKEN/$TOKEN/" /etc/aria2/aria2.conf
sudo chmod 600 /etc/aria2/aria2.conf
echo "$TOKEN"

把最后打印出来的串抄进 AriaNg 的 RPC 设置里，形如 token:xxxx。丢了就重新生成一次，代价只是所有前端要重填。

四、RPC 安全三件套：token、只听本地、反代 HTTPS

这是全文最值得认真看的一节。Aria2 的 RPC 接口权限极高：能往任意路径写文件、能执行下载完成后的钩子脚本、能读你磁盘上的内容。把它裸露在公网 6800 端口上，等同于把一个免密的管理后台挂在互联网上。安全做法是三件事叠起来，缺一不可。

第一，token 必填。rpc-secret 是方法级鉴权，每次调用都要带上 token: 前缀。官方手册明确写了它的校验被设计成「至少消耗一定时间」，用来缓解暴力破解，所以不要用短口令。

第二，只监听本地。配置里 rpc-listen-all=false 让它只绑 127.0.0.1。这样即使防火墙写错，外网也连不上；配合云厂商安全组只放行 22 和 443，双保险。

第三，用 nginx 反代并套 HTTPS。浏览器端的 AriaNg 走 https 页面时，如果 RPC 是明文 http，会被混合内容策略拦掉；更重要的是，token 在明文 HTTP 里是裸奔的。反代配置大致如下，测试环境示例，证书路径以你实际的签发方式为准（certbot 默认在 /etc/letsencrypt/live/域名/ 下）：

NGINX 
server {
    listen 443 ssl;
    server_name dl.example.com;

    ssl_certificate     /etc/letsencrypt/live/dl.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/dl.example.com/privkey.pem;

    root /var/www/ariang;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /jsonrpc {
        auth_basic "aria2";
        auth_basic_user_file /etc/nginx/.htpasswd;

        proxy_pass http://127.0.0.1:6800/jsonrpc;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}

这里加了 basic auth 是有意为之：token 泄露的方式往往不是被爆破，而是你截图、你贴配置、你换手机时忘了清剪贴板。多一层 HTTP 认证，成本几乎为零。把 AriaNg 换成静态文件也很简单，下载 release 包解压到 /var/www/ariang 即可，压缩包文件名以 GitHub Release 页面上的实际文件名为准。

五、qBittorrent-nox：把 WebUI 关进 systemd

如果你主要做种，qBittorrent-nox 更顺手。它的官方 wiki 给了一套完整流程，这里按 Debian 系复述并标注注意点，测试环境示例。

SHELL / COMMAND 
sudo apt update
sudo apt install -y qbittorrent-nox
sudo adduser qbtuser
sudo usermod -s /usr/sbin/nologin qbtuser

第一次启动必须人工跑一遍，因为要接受法律声明并拿到初始密码，这一步不能跳过，否则服务在 systemd 下会一直起不来：

BASH 
sudo su -s /bin/bash qbtuser
qbittorrent-nox
# 看到 Web UI 地址与初始账号后，Ctrl-C 退出
exit

关于初始密码有个版本差异值得记住：5.0.0 之前的版本默认是 admin / adminadmin，5.0.0 起改为首次启动时随机生成、只在控制台打印一次。所以如果你看到的不是 adminadmin，不要以为装坏了，去翻刚才那屏输出。

Debian 与 Ubuntu 的软件包通常会自带模板单元 qbittorrent-nox@.service，直接用实例化方式拉起即可：

SYSTEMD 
sudo systemctl daemon-reload
sudo systemctl enable --now qbittorrent-nox@qbtuser
systemctl status qbittorrent-nox@qbtuser
journalctl -u qbittorrent-nox@qbtuser -f

如果你的发行版没有自带单元文件，可以自己写一个最小版本放到 /etc/systemd/system/ 下。注意 Type 用 simple、让进程前台运行，不要同时开 daemon 参数，否则 systemd 会误判服务已退出：

SYSTEMD 
[Unit]
Description=qBittorrent-nox
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=qbtuser
Group=qbtuser
ExecStart=/usr/bin/qbittorrent-nox
Restart=on-failure
RestartSec=5
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target

WebUI 默认监听 8080，也就是 所有网卡。装完第一件事就是登进去改端口或改监听地址，再套一层和上一节同款的反代。BT 监听端口通常是 6881 起的 TCP/UDP 段，做种要在防火墙和商家安全组里放行，否则别人连不上你，上传自然上不去。

六、磁盘规划：别让做种把系统盘写满

下载机最常见的「事故」不是被攻击，而是盘满。盘一满，aria2 会报 I/O 错误、qBittorrent 会卡在检查、systemd 日志也写不进去，最后连 SSH 都登不上。规划上建议把三类数据分开：

用途建议介质容量起点说明
未完成任务 / 缓存NVMe SSD40–80 GB随机写多，放系统盘外的独立分区更安全
完成归档 / 长期做种HDD 或对象存储500 GB 起顺序写为主，单位容量成本最低
会话与配置系统盘1 GB 以内aria2.session 与 .conf 放这里即可

几个具体做法。给下载目录单独挂一块盘或单独分区，挂到 /srv/downloads，这样写满也只影响下载，不影响系统。设置 inode 与配额，大量小文件（比如数据集）会先耗光 inode 而不是容量，xfs 可以在挂载时限制。定期清理用 find 按天龄删除，比手工 rm 靠谱：

SHELL / COMMAND 
# 删除 30 天前修改过的已完成文件（测试环境示例，先跑 -print 确认再改成 -delete）
find /srv/downloads/completed -type f -mtime +30 -print

还有一件小事：SSD 的写入寿命。做种本身读多写少，但 BT 分片校验和频繁的小写入对廉价 SSD 不友好。预算允许的话，缓存盘用带 DRAM 的 TLC，别用无缓的 QLC 叠瓦货。

七、带宽规划：先把流量账算明白

算账比调参重要。一个粗略的换算是：持续 10 MB/s 跑满 24 小时，约消耗 0.85 TB。也就是说，一台月流量 2 TB 的机器，按这个速度跑不到三天就用完了。所以第一步不是买大带宽，而是确认三件事：月流量额度、超量后的处理方式（限速还是停机）、以及是否对 BT 流量单独计费。

第二步是限速而不是硬跑满。aria2 的全局下载限速用 max-overall-download-limit，单任务用 max-download-limit，单位是字节每秒，支持 K/M 后缀；qBittorrent 在 WebUI 的「速度」页里直接填。把夜间高峰让出来，既能减少被邻居投诉的概率，也让自己的任务更稳。

第三步是并发数。max-concurrent-downloads 调到 20 并不会更快，反而会让每个任务的连接分摊变薄、磁盘随机写放大。5 到 10 是 home server 的常见甜点区，具体看盘的类型。

八、BT 做种与版权合规：这一节请务必读完

BT 本身是中立技术，但你下载和分发的内容决定了这件事是否合法。合法的场景其实很多：Linux 发行版 ISO、开源软件与数据集、公有领域作品、以 CC 协议发布的音乐与影片、你自己拥有版权或已获授权的素材。除此之外，尤其是商业影视、音乐、付费课程、正版软件破解版，在任何机房都不是「技术问题」而是「法律问题」。

更要紧的是商家 AUP。几乎所有 VPS 商家的可接受使用政策里都有「不得侵犯知识产权」「不得进行未经授权的文件分发」的条款，且多数会在收到 DMCA 或 abuse 投诉后先限速、再停机、最后清退，退款视条款而定。共享 IP 的机器上，同一个 IP 上别人的行为也可能让你的 IP 段被整体标记，这是很多人「什么都没干却被封」的真实原因。

实践上建议：只订阅你确实有权获取的种子；把上传限速设低；不要用 VPS 搭公开 tracker 或做 PT 刷流；收到投诉邮件第一时间处理而不是无视；不要把下载目录做成公开的 HTTP 目录列表。这五条能挡掉九成以上的麻烦。

九、和网盘、对象存储配合：下载完就搬走

VPS 的盘贵且小，网盘和对象存储便宜且大，所以最常见的架构是「VPS 只做中转」。Aria2 提供了下载完成钩子，可以在任务结束时自动触发归档脚本：

SHELL / COMMAND 
# /etc/aria2/aria2.conf 中追加（测试环境示例）
on-download-complete=/usr/local/bin/aria2-archive.sh

钩子脚本里做的事就一行：把完成的文件用 rclone 搬到远端，然后删本地副本。rclone 支持 S3 兼容存储、WebDAV、各家网盘，配置好 remote 之后：

SHELL / COMMAND 
rclone copy /srv/downloads/completed remote:vps-archive --transfers 4 --checkers 8
rclone delete --min-age 7d remote:vps-archive

有几个坑要提前知道。不要把对象存储直接挂成 aria2 的下载目录：aria2 需要 preallocate 和随机写，对象存储按请求计费、延迟高，挂上去之后任务会以各种奇怪的 I/O 错误失败。正确顺序永远是本地盘写完再搬。注意出网流量费，对象存储的下载（egress）通常单独计费，而上传一般便宜甚至免费，所以「VPS 下载 → 上传到对象存储 → 家里从对象存储拉」这个链路，成本主要落在最后一段。

十、排障清单：先看这四个地方

任务不动时，按这个顺序查，比乱改配置快得多。第一，看服务状态：systemctl status 与 journalctl -u 服务名 -e，九成问题在日志里已经写清楚了。第二，看磁盘：df -h 与 df -i，容量和 inode 任意一个满了都会表现为「下载卡住」。第三，看端口：ss -lntp 确认 6800 或 8080 只绑在 127.0.0.1 上，BT 端口是否在监听，再用外部工具测一下是否可从公网连通。第四，看权限：下载目录的属主是否和运行用户一致，SELinux 或 AppArmor 有没有拦。

另外提醒一句：改动配置后记得 systemctl daemon-reload。很多人改了单元文件却发现「没生效」，其实只是 systemd 还在用旧的内存副本。

常见热点问题解答 (FAQ)

Aria2 和 qBittorrent 能同时跑在一台 VPS 上吗？

可以，但要错开 RPC 与 WebUI 端口、分开下载目录，并分别设好会话文件。两者都会维护自己的 DHT 表与连接池，1 GB 内存以下的小机器建议只留一个，否则很容易被 OOM Killer 干掉。

设了 rpc-secret 还是被人连上了，怎么办？

先确认 rpc-listen-all 是 false，再用 ss -lntp 看 6800 是否真的只绑在 127.0.0.1。如果它绑在 0.0.0.0，说明配置文件没被读到，检查 ExecStart 里的 conf-path 是否写对。最后在安全组只放行 443。

下载很快，但做种上传几乎为零？

多数情况是 BT 监听端口没有在商家安全组或本机防火墙放行，别人连不进来。先在客户端里看「可连接」状态，再查 ufw / firewalld 规则；其次是种子本身做种者太少，跟你无关。

VPS 商家会因为 BT 流量封号吗？

会。多数 AUP 明令禁止未经授权的内容分发，收到 DMCA 或 abuse 投诉后通常先限速再停机。只下载你有权使用的内容、把上传限速压低，是最稳妥的做法。

能不能把下载目录直接挂在对象存储上？

不建议。aria2 需要预分配与随机写，对象存储按请求计费且延迟高，挂载后常出现莫名的 I/O 错误。标准做法是本地盘下载完成，再用 rclone 归档。
