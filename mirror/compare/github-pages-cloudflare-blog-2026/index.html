二、GitHub Actions 自动化 CI/CD 构建工作流配置

坚决放弃本地手动 npm run build 后把打包文件传到仓库的陈旧做法！采用 GitHub Actions 自动化 CI/CD，你只需在任何设备（包括手机或 iPad）上向仓库的 main 分支提交一篇 Markdown 文章，GitHub 云端虚拟机会在 10 秒内自动编译并将生成的静态 HTML 推送到部署分支 gh-pages。

1. 仓库分支设计推荐

  • main 分支：存放博客源码（Markdown 文章、主题配置、前端模板、图片源文件）。
  • gh-pages 分支：由 GitHub Actions 自动化生成并覆盖写入打包产物（纯静态 index.html、CSS、JS）。在仓库 Settings -> Pages 中指定从该分支发布。

2. 生产级 .github/workflows/deploy.yml 配置清单

以当前最主流的高性能引擎 Hugo 为例（若采用 Astro 或 VitePress 只需更换构建步骤）：

SHELL / COMMAND 
name: Deploy Blog to GitHub Pages

on:
  push:
    branches:
      - main # 监听 main 分支的提交更新
  workflow_dispatch: # 支持在 GitHub 网页上手动点击一键触发构建

# 赋予 GitHub Actions 写回 gh-pages 分支的必要权限（关键配置！）
permissions:
  contents: write

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Source Code
        uses: actions/checkout@v4
        with:
          submodules: recursive # 如果主题使用了 git submodule，必须递归拉取
          fetch-depth: 0        # 拉取完整提交历史，保证文章更新时间戳准确

      - name: Setup Hugo
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: 'latest'
          extended: true # 启用 Extended 版本，支持 Sass/SCSS 编译

      - name: Build Static Site
        run: hugo --minify

      - name: Deploy to gh-pages Branch
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public # Hugo 默认输出目录，Astro 请改为 ./dist
          publish_branch: gh-pages
          cname: yourdomain.com # 自动向 gh-pages 根目录写入 CNAME 文件，防止被覆盖丢失！

⚠️ 致命避坑点：在 actions-gh-pages 中务必声明 cname: yourdomain.com！因为每次构建推送到 gh-pages 会清空该分支，如果没有配置该参数，GitHub Pages 根目录下的 CNAME 文件会被抹除，导致自定义域名绑定失效！

三、Cloudflare 域名解析与 CNAME Flattening（CNAME 扁平化）

很多新手在给根域名（Apex Domain，例如 yourdomain.com，没有 www 前缀）配置解析时会陷入困惑：根据互联网权威标准 RFC 1034 规范，根域名不允许直接配置 CNAME 记录！如果把根域名配置为 CNAME，会导致该域名下的 MX（邮件）等其他记录全部失效。

Cloudflare 的黑科技：CNAME Flattening 原理

Cloudflare 是全球首家在权威 DNS 服务器底层实现 CNAME Flattening（扁平化） 的厂商：
• 你在控制台可以自由地为 @ 根域名添加一条目标为 yourname.github.io 的 CNAME 记录。
• 当外部用户向 Cloudflare 发起 DNS 查询时，Cloudflare 的 DNS 权威服务器会在其内部毫秒级解析出 yourname.github.io 的实际 IP 地址，并以标准的 A 记录（直接返回 IPv4 地址） 返回给客户端！
• 既遵守了 RFC 1034 国际规范，又让根域名完美享受 CNAME 动态漂移的便利！

四、血泪避坑：彻底解决 ERR_TOO_MANY_REDIRECTS 重定向死循环

将 GitHub Pages 绑定自定义域名并套上 Cloudflare 后，90% 的新手都会遭遇浏览器提示“该网页出现重定向循环（ERR_TOO_MANY_REDIRECTS）”并彻底打不开网站。以下为你彻底讲透底层机理与标准解法：

1. 致命根源剖析

[访客浏览器] │ │ 1. 访问 https://yourdomain.com (HTTPS 请求) ▼ [Cloudflare Edge CDN] (若 SSL 模式被误设为 Flexible) │ │ 2. Cloudflare 将请求解密，向 GitHub 发起 HTTP 请求 (80 端口) ▼ [GitHub Pages 源站服务器] (后台勾选了 "Enforce HTTPS") │ │ 3. GitHub 发现来访是明文 HTTP，立刻返回 HTTP 301 强制跳转 https://yourdomain.com ▼ [Cloudflare Edge CDN] │ │ 4. 将 301 转发给访客浏览器 ▼ [访客浏览器] 再次访问 https://yourdomain.com ──► 陷入无限死循环！

2. 官方标准解法（三步自救法）

  1. 第一步：切为“灰云（DNS Only）”让 GitHub 完成证书签发：
    GitHub Pages 需要通过 Let's Encrypt 为你的自定义域名签发官方 SSL 证书。如果 Cloudflare 处于橙色小云朵（Proxy 代理）状态，Let's Encrypt 的 HTTP-01 验证挑战会被 Cloudflare 拦截。
    正确姿势：在 Cloudflare DNS 面板，暂时将小云朵切为“灰色（DNS Only）”。
  2. 第二步：在 GitHub 仓库启用 Enforce HTTPS：
    进入仓库 Settings -> Pages，检查 Custom domain 状态。当看到“DNS check successful”并成功签发证书后，勾选 Enforce HTTPS。
  3. 第三步：Cloudflare SSL 模式必须设为 Full 或 Full (Strict)：
    进入 Cloudflare 控制台 -> SSL/TLS -> Overview，将加密模式从 Flexible 彻底改为 Full 或 Full (Strict)！
    重新将 DNS 记录切回 橙色小云朵（Proxied）。此时 Cloudflare 到 GitHub 全程通过 443 端口加密握手，死循环彻底消失，全站享受绿锁秒开！

五、国内访问加速与双轨智能解析策略

由于 GitHub Pages 的官方 IP 节点全部分布在美欧地区，且 Cloudflare 免费 Anycast AnyIP 国内运营商路由偶尔会绕道美西甚至出现丢包。如果你希望进一步提升国内访客的秒开体验，推荐采用双轨智能解析方案：

  • 海外访客：通过 Cloudflare CDN 全球 Anycast 加速，享受极速缓存与全量 WAF 防火墙保护。
  • 国内访客分流：在具有智能分流能力的 DNS 服务商（如 DNSPod、华为云 DNS）处配置：
    • 海外路线（默认）：CNAME 指向 yourname.github.io（通过 Cloudflare 代理）。
    • 国内路线（电信/联通/移动）：CNAME 解析至 Vercel 或 Cloudflare Pages。由于 Vercel 与 Pages 在亚太地区的边缘回源策略对国内网络更加友好，可以显著降低首屏白屏时间。

六、SEO 优化与搜索引擎自动化提交

独立博客要获得持久的自然流量，必须做好搜索引擎优化与爬虫指引：

  1. 自动生成规范的 Sitemap 与 Robots.txt：
    Hugo 与 Astro 默认会在打包时自动在根目录生成 sitemap.xml。请确保在 robots.txt 中指引其绝对地址：
    SHELL / COMMAND 
    User-agent: *
Allow: /
Sitemap: https://yourdomain.com/sitemap.xml
  2. 在 Cloudflare WAF 中特别放行主流蜘蛛：
    进入 Cloudflare Security -> WAF -> Custom Rules，添加一条规则：当 cf.client.bot 为 true，或者 User-Agent 包含 Googlebot|bingbot|Baiduspider 时，操作设置为 Skip（跳过所有安全质询），彻底杜绝搜索引擎爬虫抓取时遭遇 5秒盾 或验证码拦截。
  3. 配置 IndexNow 协议实现即时收录：
    在 GitHub Actions 部署脚本末尾加入一条向 Bing / Yandex 的 IndexNow API 请求，每当有新文章发布，自动通知搜索引擎毫秒级抓取最新 URL。

常见热点问题解答 (FAQ)

Q1：GitHub Pages 免费托管有容量或带宽限制吗？

A1：GitHub Pages 官方推荐单个仓库体积不要超过 1GB，每月出站流量软性上限为 100GB。配合 Cloudflare 全球边缘 CDN 强效缓存后，99% 的静态资源直接在 Cloudflare 节点返回，GitHub 仓库每月的实际出站流量消耗通常连 1GB 都不到，永远不必担心超额。

Q2：如果不想买域名，可以直接用 github.io 域名套 Cloudflare 吗？

A2：不能。Cloudflare 的 CDN 代理服务要求你必须拥有一个专属的顶级域名，并将该域名的 Nameservers（NS 记录）委派给 Cloudflare 管理。目前 .com 或 .xyz 等常见域名年费仅需几美元，属于极其微小的投资。

Q3：静态博客如何实现访客评论系统？

A3：完全不需要自建数据库！目前业界流行两种 0 元免费方案： Giscus / Utterances：基于 GitHub Discussions / Issues 的纯静态评论系统，访客通过 GitHub 登录留言，数据直接保存在你的 GitHub 仓库中，0 运维成本。
