一、为什么想自己搭域名邮箱

很多人第一次想自建邮件服务器，是因为受够了第三方邮箱的种种限制：要么按席位收费、要么随便扫描你的邮件内容做广告、要么哪天政策一变就限流。自己用 Mailcow 搭一套，好处很直接：完全的数据所有权、无限的邮箱别名（比如每个网站用不同别名，泄露了就知道是谁卖的）、以及不被 SaaS 厂商卡脖子的自由。

但先说一句大实话：自建邮件是「运维长跑」，不是「装完就完事」。软件本身真的不难，Mailcow 把 Postfix、Dovecot、Rspamd、SOGo 这些东西打包成一个 Docker 容器栈，照着文档半小时就能跑起来。真正难的是送达率——整个互联网对一台崭新的邮件服务器是天然不信任的。本文不灌鸡汤，直接讲清三道生死线，以及各家 VPS 在端口和 IP 上的真实情况。

二、三个生死线总览

在租用任何机器、执行任何安装命令之前，请先确认下面三件事。缺任何一条，你发出去的信都会「不报错、不弹回、直接消失在虚空里」，这种沉默失败最难排查。

  • 生死线一：25 端口是否开放。服务器之间投递邮件走 TCP 25。很多云厂商和廉价 VPS 默认在底层封锁出向 25，理由是防垃圾邮件。封锁是静默的，开机一切正常，只是信永远堆在队列。
  • 生死线二：IP 是否进了黑名单。VPS 的 IP 常被上一任租户滥发垃圾邮件而进了 RBL（实时黑名单）。新 IP 若已上榜，Gmail、Outlook 直接拒收，这不是改配置能救的。
  • 生死线三：PTR 反向解析是否对齐。PTR 要把服务器 IP 指回你的邮件主机名，且必须和 Postfix 宣告的 HELO 名一致。PTR 不在你的域名面板设，而在 VPS 商家控制台。

下面三节逐一拆开讲，并附上自测命令。

三、生死线一：25 端口怎么测、被封怎么办

先测再装，别浪费时间。在一台你已经拿到手的 VPS 上执行：

SHELL / COMMAND 
nc -vz -w 5 gmail-smtp-in.l.google.com 25

如果看到 succeeded，说明 25 是通的；如果卡满 5 秒后报 timed out，那就是商家在底层封了。这个超时是商家侧的网络过滤，不是你防火墙的问题，本地改任何设置都没用。

被封了只有两条路：开工单让商家解封，或者换一家本来就不封的。这里有个必须诚实指出的事实——常见认知和真实情况恰好相反。很多文章说 Vultr、Contabo 默认放行、RackNerd 要工单，但联网核实后并非如此：

商家25 端口默认发送限制PTR 设置真实备注
Vultr默认封锁解封后无统一上限控制台可设官方文档明确 TCP 25 默认 blocked，需开 support ticket 解封，且有邮件基础设施公司两次申诉仍被拒的公开案例
Contabo默认开放新账号约 25 封/分钟控制台可设配置高、性价比突出；IP 信誉波动，需自己慢慢预热
RackNerd默认开放无明确限制控制台可设多个 2025-2026 评测确认 open by default、unlimited outbound，是公认最 email-friendly 的廉价商家之一

所以如果你只想「开箱即发」，Vultr 反而是最容易踩坑的那家——它默认封 25，而 Contabo 和 RackNerd 反而默认放行。选机器前一定先确认端口政策，别等装完才发现信发不出去。

四、生死线二：IP 信誉与黑名单自查

即使 25 端口是通的，如果这台机器的 IP 之前被拿去发垃圾邮件，现在正躺在 Spamhaus 或 UCEPROTECT 的黑名单里，Gmail 照样会把你拒之门外。廉价 VPS 的超售「灵车」厂商 ASN 底层信誉差，即便你 SPF/DKIM/DMARC 配得再完美，巨头平台也可能因为 ASN 级别的不信任把你打进冷宫。

买机器前后，务必做两件事：

  • 查黑名单：用 mxtoolbox 的 blacklists 工具查你的 IP 是否上了 Spamhaus、Barracuda、Cisco Talos 等主流 RBL。命中多个就直接申请换 IP 或退款换机器，别在脏 IP 上死磕。
  • 优先选干净 ASN：老牌、有反滥用机制的商家，IP 段相对干净；极度超售的廉价厂商要慎重。

如果 IP 已经黑了且申诉无门，靠这台机器自己发信就不现实了。这时就用第八节讲的混合中继兜底。

五、生死线三：PTR 反向解析必须对齐

PTR（反向 DNS）是「用 IP 反查主机名」。Gmail 的政策写得明明白白：发信 IP 如果没有 PTR，或者前向（A 记录）和反向（PTR）对不上，会直接拒收，报错码就是 550 5.7.25。

关键点：PTR 不在你的域名注册商面板设，而在持有这个 IP 的 VPS 商家那里设——通常在控制台的网络设置里，或者开一张工单让客服帮你把 IP 的 PTR 指到 mail.example.com。设完用命令验证：

SHELL / COMMAND 
dig -x 你的服务器IP +short

返回结果应当是 mail.example.com. 结尾。同时，你的 Postfix 宣告的 HELO 名、TLS 证书主体、MAILCOW_HOSTNAME、MX 指向的主机名，全部要用同一个名字，差一个字母都不行。

六、四张 DNS 牌：MX / SPF / DKIM / DMARC

DNS 是绝大多数自建邮件翻车的地方。四张记录缺一不可，作用各不相同：

记录类型名称值（示意）作用
MXyourdomain.com10 mail.yourdomain.com告诉全世界邮件往哪投
SPFyourdomain.comv=spf1 mx -all声明哪些服务器能代表你发信
DKIMdkim._domainkeyv=DKIM1; k=rsa; p=公钥给每封邮件做加密签名
DMARC_dmarcv=DMARC1; p=quarantine校验失败时的处置策略

DKIM 的公钥由 Mailcow 自动生成，你去域名面板发一条 TXT 即可。两个高频坑：

  • Cloudflare 别给 MX 开橙云。邮件流量必须直连你的服务器，橙色云（代理）会让 Gmail 看到的不是你的真实 IP，认证链全乱。MX 记录要设成 DNS-only 灰云。
  • 等传播。改完 DNS 后 DKIM 失败常常是没等够 TTL，先睡一觉再测，别急着改来改去。

七、Mailcow 一键栈：装前准备

Mailcow 把整套邮件服务打包成了 Docker Compose 栈，安装本身不复杂：

SHELL / COMMAND 
git clone https://github.com/mailcow/mailcow-dockerized
cd mailcow-dockerized
./generate_config.sh
docker compose pull
docker compose up -d

但装之前把硬件和命名想清楚：

  • 内存：官方最低 6 GiB RAM + 1 GiB swap，用户一多建议 8 GiB。低于 2.5 GiB 时脚本会建议你关掉 ClamAV 病毒扫描，否则内核会杀容器。
  • 磁盘：起步 20 GB SSD 起，邮件和数据库会慢慢涨。
  • 主机名一致：MAILCOW_HOSTNAME、TLS 证书、PTR 目标、SMTP banner 全部用同一个 mail.example.com，这是最容易被忽略的隐性坑。

装完登录管理面板，添加域名和邮箱，把 DKIM 公钥抄到域名 DNS，再用 mail-tester 打分。

九、验证与预热：先打到 10/10 再发真信

装好不等于能用。先做送达率自检：

  • 用 mail-tester 发一封测试信，看分数。目标 10/10；低于 8 基本就是 SPF/DKIM/PTR 某处没对齐。
  • 在 Gmail 收件后点「显示原文」，看 auth results：spf=pass、dkim=pass、dmarc=pass 三者全绿才算过关。

分数 OK 之后，千万别第一天就群发几千封。新 IP、新域名的初始信誉是零，必须预热：

  • 第 1 周：每天 20-50 封，只发给会主动回复你的熟人/老客户。
  • 第 2 周：提到 100 封，循序渐进。
  • 千万别导入几万名单去群发外贸开发信，那会瞬间触发巨头防滥用机制，域名可能被永久标记。

十、兜底方案：发信用 SMTP 中继混合架构

如果 25 死活解不开（比如 Vultr 工单被拒），或者 IP 信誉实在养不起来，还有一条务实的退路：自建收 + 第三方中继发的混合架构。

思路是：你的 Mailcow 照常负责收信、存信、IMAP、DKIM 签名、垃圾过滤；唯独「外发到对方服务器」这一步，交给 Amazon SES、Mailgun、SendGrid 这类商业 SMTP 中继（smarthost）去完成。它们有自己的干净 IP 池和成熟信誉，相当于借别人的好名声把信送出去。

这种混合架构适合「域名必须 100% 到达率」的场景。代价是要配置中继账号、留意每月免费额度，以及遵守中继商的发送规范。但比起在脏 IP 上死磕，这往往是更稳的选择。

十一、面向大陆用户：免备案、支付与诚实的维护成本

把视角拉回大陆用户最关心的几件事：

  • 免备案：海外 VPS 天然免备案，这是自建邮件出海、做外贸域名邮箱的常见前提。
  • 支付：RackNerd、部分商家支持支付宝，对国内友好；Contabo、Vultr 走信用卡/PayPal/加密。
  • 退款：各家窗口不同，以商家页面为准；关键是买前先查 IP 黑名单，命中多直接换机比事后申诉省事。
  • 线路/延迟：邮件服务对延迟不如网站敏感，但管理面板、Webmail 体验受线路影响，选离你近或有优化线的机房更顺手。

最后说实话：自建邮件是「控制欲换便利」的取舍。如果你只是想要一个自己域名的邮箱、且愿意偶尔看日志、做备份、养 IP，Mailcow 是 2026 年依然能打的方案；如果你的业务邮箱一天进垃圾箱就亏钱，那托管方案更省心。本文只帮你把三道生死线看明白，决定权在你。

十二、结语

Mailcow 的软件部分，半小时能跑起来；真正的功课在它之外——25 端口通不通、IP 干不干净、PTR 对不对齐、四张 DNS 牌全不全。把这四件事做对，再用 mail-tester 打到 10/10、慢慢预热 IP，你的信就能稳稳进收件箱而不是垃圾箱。

选商家时记住本文核实过的真实情况：Contabo 与 RackNerd 默认放行 25，Vultr 反而要工单且常被拒。租机前先测端口、查黑名单，能省掉后面 90% 的抓狂。祝你自建顺利， inbox 常青。

常见热点问题解答 (FAQ)

25 端口被封了，是不是就彻底没法自建邮件服务器？

不是。被封只有两条路：开 support ticket 让商家解封，或换一家默认放行 25 的商家（如 Contabo、RackNerd）。实在解不开，还能用第八节讲的 SMTP 中继混合架构，让第三方帮你把信送出去。

Mailcow 最少要多少内存才跑得稳？

官方最低要求 6 GiB RAM 加 1 GiB swap，2-3 个邮箱的低量场景够用；用户变多或开全量反垃圾，建议上 8 GiB。内存低于约 2.5 GiB 时脚本会建议关 ClamAV 与 Solr，否则内核 OOM 会杀容器，造成收发中断。

SPF、DKIM、DMARC 没配全会怎样？

四张 DNS 牌缺一不可：SPF 声明发件服务器，DKIM 用公钥验签，DMARC 定策略收报告，PTR 反向解析要对齐主机名。任一项写错，mail-tester 低于 8 分、Gmail 直进垃圾箱。按第六节的示意记录逐条对齐，打到 10/10 再发真信。

大陆用户选哪家最省心？

想稳定发信，Contabo 默认开放 25、配置高最省心，但新号限速需预热；RackNerd 同样默认开放 25 且支持支付宝，性价比高；Vultr 反而要开工单且常被拒，新手别踩坑；IP 进黑名单优先换商家干净 IP。

新域名、新 IP 第一天就能群发吗？

绝对不能。新 IP 初始信誉为零，必须预热：第 1 周每天 20-50 封发给会真实回复的人，第 2 周提到 100 封，循序渐进。千万别一上来导入几万名单群发，会被 Gmail 秒进垃圾箱甚至拉黑整个子网。配合 DMARC 报告观察投递率，信誉稳了再放量。
