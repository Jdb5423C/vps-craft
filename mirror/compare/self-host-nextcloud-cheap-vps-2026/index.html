一、为什么要自建私人网盘

把照片、文档、家庭录像塞进百度网盘或 OneDrive，大多数人图的是省事。但用久了会发现几件事：免费容量越来越不够，不开会员下载被限速；会员涨价说涨就涨；更关键的是，文件躺在别人的服务器上，是否被人看过、是否被拿去训练模型，你其实并不知道。对于在意隐私、又想长期持有数据的用户，用一台便宜的国外 VPS 自建 Nextcloud 私人网盘，是一条很实在的路。

Nextcloud 是开源的自托管网盘，功能上对标 Dropbox / Google Drive，但数据完全在你自己的机器上。它支持多端同步（Windows / macOS / Linux / iOS / Android）、文件版本控制、共享权限、在线协作编辑（装 OnlyOffice 或 Collabora），还能顺手替代日历、联系人、笔记。下面我们把搭建过程、VPS 选型、流量与存储的取舍一次讲清楚。

二、Nextcloud 到底要吃多少资源

先说结论：个人或小家庭使用，2 核 4GB 内存是舒服的起点；纯文档同步 1 核 2GB 也能跑，但装插件、生成缩略图、多用户同时上传时会明显吃力。磁盘方面，取决于你塞什么进去：

使用场景建议 VPS 存储
只存文档25–50 GB
文档 + 部分照片50–100 GB
完整照片库200–500 GB
家庭云盘（2–4 人）200–500 GB
小团队（5–10 人）500 GB – 1 TB

软件栈推荐 Ubuntu 22.04 LTS，搭配 Apache/Nginx + PHP 8.1 以上 + MariaDB/MySQL。想让网页加载快，强烈建议上 Redis 或 APCu 缓存——实测开启后页面速度快一倍不止。PHP 的几个参数也要放宽：memory_limit 提到 512M，upload_max_filesize 和 post_max_size 根据实际最大文件设到几 GB 到十几 GB，max_execution_time 设 3600，否则传大文件会超时失败。

另外，Nextcloud 的「应用商店」里有上百个插件，做网盘最值得装的几个是：Calendar（日历同步）、Contacts（联系人）、Notes（Markdown 笔记）、Talk（视频会议）、Photos（照片时间线）。如果你想要网页版 Office，可以装 Collabora 或 OnlyOffice，但这两个对内存要求更高，2GB 机器不建议硬上，至少 4GB 起步才稳。新手先别贪多，把文件同步跑顺再说。

四、Contabo：大硬盘性价比之王，但要接受超售

如果你要的是「一台机器塞下整个家庭照片库 + 影视备份」，Contabo 几乎是无脑首选：4 核 8G、200GB SSD、32TB 流量，月付不到 5 欧；上到 800GB 也才十几欧。它还免费送一个快照、自带基础 DDoS 防护、支持 Windows（另加约 €4.99/月），机房覆盖德国、美西、美中、英国、新加坡、日本、悉尼。

但我们得诚实说缺点，这些坑很多人踩过：

  • 磁盘 IO 是短板。实测 4K 随机读写 IOPS 在 2000–3000 左右，顺序读写 140–200 MB/s，体验接近机械盘。Nextcloud 生成缩略图、全文搜索时会感到卡。
  • 超售明显。低价来自激进超售，欧洲白天（国内凌晨）IO 还会进一步劣化。
  • 工单慢。非紧急问题 24–72 小时才回，没有在线聊天、没有电话，也没公布 SLA，实测一年在线率约 99.85%，不算高。
  • 开通慢 + 需验证。付款后人工审核，通常等 24–72 小时；用 PayPal 付款大概率要传护照/身份证照片。
  • 对国内延迟高。德国机房到国内 300ms+，美国机房 180–260ms，SSH 操作都有感。不适合面向国内高频访问。

总结：把 Contabo 当成「海量冷存储 + 备份」很香，别把它当「对延迟敏感的正式生产服务」。

五、RackNerd / CloudCone / Virtono：流量大方但硬盘小

RackNerd 是 LowEndTalk 社区常年好评的低价商家，黑五款 1核1G/25GB/2TB 年付只要约 $10.6，且续费同价，支持支付宝。最高配 6核8G/150GB/20TB 也才约 $62.5/年。缺点就是硬盘小，做主力网盘不够，但跑 Nextcloud 放文档 + 挂对象存储非常合适。

CloudCone 洛杉矶机房对国内相对友好，全系 RAID-10 SSD、1Gbps 端口。SSD VPS 6 给到 10核16G/223GB/6TB，年付约 $170。同样硬盘不算大，但 IO 比 Contabo 稳。

Virtono 卖点是无限流量（100Mbps 端口）、€1.5/月起，但内存最小 256MB、硬盘 20–60GB，机房都在欧洲（罗马尼亚/英国/荷兰/德国），对国内延迟高。更适合当异地备份副本或同步节点，而不是主力网盘。

六、聪明的折中：VPS 跑应用 + 对象存储存冷数据

最划算的架构是「VPS 只跑 Nextcloud 程序和近期热数据，大文件丢到 S3 兼容对象存储」。这样你买一台 RackNerd / CloudCone 的小硬盘机器就够，冷数据用 Wasabi（约 $6.99/TB/月，无出口流量费）或 Backblaze B2（约 $6/TB/月，无出口费）扩容。Nextcloud 的「外部存储」应用原生支持 S3，挂载后在界面里就是一个普通文件夹，分享、搜索都照常。

七、动手搭建：Ubuntu 22.04 + LAMP 安装 Nextcloud

下面是最直接的手动安装流程（以 Apache 为例）。先装运行环境和数据库：

BASH 
sudo apt update
sudo apt install -y apache2 mariadb-server php php-gd php-json php-mysql
sudo apt install -y php-curl php-mbstring php-intl php-imagick php-xml php-zip php-apcu php-redis redis-server

创建数据库：

SHELL / COMMAND 
sudo mysql -u root
CREATE DATABASE nextcloud;
CREATE USER 'nextcloud'@'localhost' IDENTIFIED BY 'your-strong-password';
GRANT ALL PRIVILEGES ON nextcloud.* TO 'nextcloud'@'localhost';
FLUSH PRIVILEGES;
EXIT;

下载并解压 Nextcloud，修正权限：

BASH 
cd /var/www/
sudo wget https://download.nextcloud.com/server/releases/latest.tar.bz2
sudo tar -xjf latest.tar.bz2
sudo chown -R www-data:www-data /var/www/nextcloud

申请 SSL 证书（需先有域名解析到这台机器）：

SHELL / COMMAND 
sudo apt install -y certbot python3-certbot-apache
sudo certbot --apache -d cloud.yourdomain.com

浏览器打开 https://cloud.yourdomain.com，按引导填数据库和管理员账户即可完成。

八、更省事：Docker Compose 一行起服务

不想折腾 PHP 环境，用 Docker 最干净。新建 docker-compose.yml：

DOCKER 
version: '3'
services:
  db:
    image: mariadb:11
    environment:
      - MYSQL_ROOT_PASSWORD=rootpass
      - MYSQL_DATABASE=nextcloud
      - MYSQL_USER=nextcloud
      - MYSQL_PASSWORD=dbpass
    volumes:
      - db:/var/lib/mysql
  redis:
    image: redis:7
  app:
    image: nextcloud:29
    ports:
      - "8080:80"
    links:
      - db
      - redis
    volumes:
      - data:/var/www/html
volumes:
  db:
  data:

然后启动：

SHELL / COMMAND 
docker compose up -d

访问 http://服务器IP:8080 完成初始化。注意把 8080 端口用 Nginx 反代并套上 HTTPS 才安全。

九、性能优化：Redis 缓存 + PHP 调优

装好别急着用，先改 /var/www/nextcloud/config/config.php 开启缓存：

SHELL / COMMAND 
'memcache.local' => '\OC\Memcache\APCu',
'memcache.distributed' => '\OC\Memcache\Redis',
'memcache.locking' => '\OC\Memcache\Redis',
'redis' => array(
  'host' => 'localhost',
  'port' => 6379,
),

再调 /etc/php/8.1/apache2/php.ini：

SHELL / COMMAND 
memory_limit = 512M
upload_max_filesize = 16G
post_max_size = 16G
max_execution_time = 3600
opcache.enable = 1
opcache.memory_consumption = 128

这两步做完，列表加载和缩略图生成会顺滑很多，尤其在 Contabo 这种 IO 弱的机器上效果明显。

十、挂载 Wasabi / Backblaze B2 扩容

在 Nextcloud 后台「应用」里启用 External storage support，进「管理 → 外部存储」，类型选 Amazon S3（兼容），填入对象存储的 bucket、Endpoint、Region、Key ID、Application Key，勾选 Enable SSL。Wasabi 美东端点形如 s3.us-east-1.wasabisys.com，B2 端点形如 s3.us-west-004.backblazeb2.com。出现绿色对勾即挂载成功，文件会出现在左侧文件列表里。

进阶玩法：把对象存储设为主存储（改 config.php 的 objectstore），适合数据量远超 VPS 硬盘的场景，但配置更复杂，新手建议先用外部存储方式。

十一、安全与备份

  • 禁用 SSH 密码登录，只用密钥；UFW 只开 22/80/443。
  • 用 occ 命令定期备份：sudo -u www-data php occ maintenance:mode --on 后打包 data 目录与数据库。
  • 对象存储本身有版本和冗余，但仍建议再异地留一份；Nextcloud 的「文件版本」和「回收站」能挡住误删。
  • 开启两步验证（TOTP 应用），别让网盘裸奔在公网。

十二、真实体验与避坑

综合多方实测：Contabo 当大容量备份盘非常值，但别指望它 IO 多猛，缩略图和搜索慢一点要能接受；RackNerd / CloudCone 的小硬盘机器配对象存储是「体验最好 + 成本可控」的组合，尤其适合国内用户走 LA 机房；Virtono 更适合欧洲用户或做冷备。

还有几个容易忽略的点：Nextcloud 的预览图会悄悄吃掉大量空间，定期清理 data/.../cache 有用；终端用户手机自动备份照片很爽，但要算好流量——Contabo 32TB 基本用不完，小机器几 TB 流量传满家庭照片库要悠着点。

结语

用便宜 VPS 自建 Nextcloud，最大的价值不是省钱（算下来未必比会员便宜多少），而是数据真正归你自己。选型上，要容量就上 Contabo 大硬盘，要稳定和体验就 RackNerd/CloudCone 小盘 + 对象存储。本文提到的价格与促销均为撰写时的参考，具体规格、价格与流量上限请以商家当前页面为准。动手前先拿一台最便宜的机器练手，跑通流程再决定要不要升级，是最稳妥的路线。

常见热点问题解答 (FAQ)

1 核 2G 能跑 Nextcloud 吗？

纯文档同步、少量文件可以，但装插件、生成缩略图、多用户同时上传时会明显吃力，响应变慢甚至超时。2 核 4G 才是舒服的起点，缩略图预览、日历、OnlyOffice 等才不卡。1 核 2G 建议关掉预览图生成、限制并发，只做同步盘用，别指望当全能网盘。

硬盘不够用怎么办？

用对象存储做外部存储最划算。把 Wasabi、Backblaze B2、Cloudflare R2 挂载为 Nextcloud 外部存储，冷文件和大附件丢出去，小硬盘机器也能低成本扩容，无需买大磁盘套餐。注意 B2 有下载流量费、R2 有请求费，量大的话算清账单再选，避免存储便宜流量贵。

Contabo 适合做主力网盘吗？

不太适合。Contabo 磁盘大、价格低，但 IO 弱、超售明显，对国内延迟高且晚高峰易抖，当主力网盘上传下载都难受。它更适合做冷存储、备份仓库或欧洲本地访问的场景。若用户在国内且要频繁同步，建议选 IO 更稳、大陆优化线路的机器，哪怕磁盘小一点。

Nextcloud 需要把 8080 端口裸奔在公网吗？

不需要，也不建议。Nextcloud 默认常跑在 8080，直接裸奔公网既暴露版本信息又易被扫漏洞。正确做法是用 Nginx/Caddy 反代并套 HTTPS，再用域名访问，必要时加 Basic Auth 或 Fail2ban 限制爆破。这样既安全又能用标准 443 端口，手机客户端也能稳定连接。
